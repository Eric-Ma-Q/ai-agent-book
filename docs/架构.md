# 架构

这是《深入理解 AI Agent》阅读器扩展分支的结构说明。上游阅读器负责渲染书稿，本分支在它外面加一层只在开发模式下生效的扩展：文件化的读者数据、随页问答、Harness 学习站与一个独立的 Agent 实验台。

## 组件

| 组件 | 形态 | 端口 | 职责 |
|---|---|---|---|
| Astro 阅读器 | `astro dev`（`web-astro/`） | 4321 | 渲染章节与首页、提供阅读交互；dev 模式下额外挂载扩展 |
| personal 集成 | `web-astro/personal/integration.mjs` | 同 4321 | 注册 `/__personal` 文件 API、`/__lab` 反代、Harness 静态归档、扩展页面与客户端脚本 |
| 读者数据存储 | `personal/notes`、`inserts`、`annotations`、`harness` | 无 | 划线、笔记、补充、批注、题库进度 |
| 实验台 | Python / FastAPI（`agent-lab/`） | 4330 | 书本助教 ReAct 循环、轨迹与评估、模型档案、随页问答、MCP、模拟面试 |
| 外部模型接口 | 兼容 OpenAI 的 HTTP 服务 | 由用户配置 | 生成回答；密钥只在本机 |
| 更新中心 | `web-astro/personal/update.mjs` + `scripts/update.sh` | 同 4321 | 检查 GitHub Releases、执行 fast-forward 更新与重启 |

阅读器与实验台是同机两个进程，`scripts/start.sh` 一起启动。实验台只监听回环地址，浏览器不直接访问 4330，一律经阅读器的 `/__lab` 代理。

## 请求流

### 章节页

1. 浏览器请求 `/book/chapter2/`，Astro 读取 `book/chapter2.md` 与插图，渲染正文。
2. dev 集成把扩展脚本注入页面：划线、批注、插入补充、文件预览、页眉入口与随页问答面板。
3. 划线或笔记变化时，浏览器带 `x-personal-api: 1` 调用 `/__personal/...`，服务端校验章节 key 与记录格式后写入 `personal/notes/<语言>/`。
4. 页面刷新时从同一接口读回，因此换设备、换浏览器看到的是同一份数据。

### 随页问答

1. 面板采集当前页面结构、章节与滚动位置，并在提问时截取视口。
2. `POST /__lab/page/runs` 经阅读器代理到实验台的 `/page/runs`，返回 `run_id`。
3. 实验台用同一套 ReAct 循环运行，工具包括页面切片、书稿检索、读者划线、文件与命令、代码解释器、联网搜索与抓取；回答过程通过 `/__lab/runs/<id>/events` 以 SSE 推给面板。
4. 轨迹写 `personal/lab/runs/`，截图与页面存档写 `personal/lab/page-assistant/<run_id>/`；文件写入只落在该目录下的 `workspace/`。
5. 「检验」「概念图」「回放」是同一接口的不同模式：检验追加判卷提示词，概念图用小的只读预算读本章结构，回放按轮次返回紧凑摘要而不返回正文与图片。

### 实验台

`/lab/` 页面直接调用 `/__lab/runs`、`/__lab/compare`、`/__lab/evals/*`、`/__lab/models` 等接口，实时展示每轮上下文、token、缓存命中与工具调用。模型档案由 `/settings/` 维护，实验台、随页问答与模拟面试共用。

### MCP

外部应用（Claude Code、Cursor、自建 Agent）以 `Authorization: Bearer <LAB_MCP_TOKEN>` 请求 `http://<主机>:4321/__lab/mcp`；阅读器只转发，鉴权在实验台。工具为书稿检索与阅读、读者标注读取、书本助教问答；`LAB_MCP_PERSONAL=0` 可隐藏读者数据工具。

### 更新

1. 设置页调 `/__personal/update/status` 读当前版本与缓存，点「检查更新」调 `/update/check` 访问 GitHub Releases（或回退到 tags）。
2. 「一键更新」带 `x-update-token` 调 `/update/apply`，服务端校验管理员 token 后写运行状态并 `spawn` `scripts/update.sh`。
3. 脚本 `git fetch` 后只做 `merge --ff-only`；对比前后锁文件，变化才装依赖；按 `UPDATE_RESTART_CMD` 重启；结果写 `personal/update/status.json` 与 `run-logs/update.log`。
4. 页面轮询状态并显示进度；失败时展示日志末尾，旧版本继续可用。更新不触碰 `personal/`。

## 数据位置

| 数据 | 位置 | 是否入库 |
|---|---|---|
| 书稿与插图 | `book/`、`book-*/` | 是（上游内容） |
| 划线、笔记、草稿 | `personal/notes/` | 否 |
| 插入的补充 | `personal/inserts/` | 否 |
| 阅读批注 | `personal/annotations/` | 否（自己的批注可自行保管） |
| 题库收藏与进度 | `personal/harness/` | 否 |
| 模型档案与密钥 | `personal/lab/models.json`、`models.keys.json` | 否 |
| 运行轨迹、评估、规则、记忆 | `personal/lab/` | 否 |
| 更新状态与 token | `personal/update/` | 否 |
| 日志 | `run-logs/` | 否 |

## 只读边界

- 作者的 `book*/`、`web-astro/src/`、`web-astro/public/`、`web-astro/scripts/` 不修改；扩展只挂在 `web-astro/personal/` 与 `agent-lab/`。
- 读者数据的路径只能由 `web-astro/personal/paths.mjs` 推导，请求参数先过白名单再拼路径，避免写到 `personal/` 之外。
- 随页问答的文件与命令工具被限制在只读仓库内容与 `personal/lab/page-assistant/workspace/` 内，不会改书稿与笔记。
- 更新脚本只做 fast-forward，工作区有已跟踪改动时中止，不覆盖本地修改。
- 不向上游仓库推送。

## 为什么是 dev-only

上游的静态构建要能被独立部署，也必须与本分支扩展无关。因此：

- 扩展由 `astro.config.mjs` 挂载的集成在 dev 时注册，`npm run build` 的产物不包含任何扩展页面、接口或脚本。
- 文件化存储、设置页、更新中心都需要一个常驻的服务端进程，静态文件无法提供。
- 这让上游更新可以随时合并，也避免让人误以为公开构建带有个人功能。

## 扩展点

| 位置 | 用途 |
|---|---|
| `web-astro/personal/paths.mjs` | 所有读者数据路径的唯一来源，新增数据文件先加这里 |
| `web-astro/personal/routes.mjs` | 扩展页面路径常量，服务端与客户端共用 |
| `web-astro/personal/api.mjs` | `/__personal` 路由表，新增文件 API 挂在这里 |
| `web-astro/personal/integration.mjs` | 注入页面脚本、注册页面与代理，新增入口从这里接 |
| `web-astro/personal/client/` | 浏览器脚本，按功能一目录或一文件 |
| `agent-lab/agent_lab/tools/` | 实验台工具，新增工具后同步开关与测试 |
| `agent-lab/agent_lab/mcp/` | MCP 协议、工具与路由 |
| `web-astro/personal/harness/` | Harness 归档、资料库与两个浏览器内模拟台 |

测试入口：阅读器侧 `cd web-astro && npm run test:personal`，实验台 `cd agent-lab && uv run pytest`。部署与排障见 [部署.md](部署.md)，AI 部署提示词见 [AI部署.md](AI部署.md)。
