# 开源审计：公开快照

> 公开仓库由 `scripts/export-public.mjs` 从私人工作副本生成，只复制白名单路径并做脱敏与扫描。本文说明哪些内容不公开、如何复核，不含私人环境的具体地址与账号。

## 1. 结论摘要

- 公开快照只包含阅读器源码、个人扩展的通用代码、实验台、书稿与公开文档；读者数据、部署脚本、需求文档与会话记忆不进快照。
- 导出后做两道检查：禁止路径与禁止字符串。任何命中都会让导出失败。
- 书稿与 Harness 归档按原样发布，不做内容改写；归档内涉及的第三方资料保留原链接与署名。

## 2. 逐目录判定

| 目录 | 是否公开 | 说明 |
|---|---|---|
| 书稿与多语言版本 | 是 | 作者内容，原样复制 |
| `web-astro/src`、`web-astro/public` | 是 | 阅读器与静态资源 |
| `web-astro/personal` | 是 | 个人扩展的通用实现与测试 |
| `agent-lab/agent_lab`、`evals`、`tests` | 是 | 实验台与评估代码 |
| `personal/notes`、`inserts`、`annotations` | 否 | 读者数据 |
| `personal/lab` | 否 | 运行轨迹、评估报告、模型档案 |
| `personal/deploy` | 否 | 本机部署与运维脚本 |
| `docs/dev/requirements` | 否 | 私人需求与设计记录 |
| `MEMORY.md`、`.claude/` | 否 | 会话记忆与本地助手配置 |

## 3. 敏感项

### 3.1 读者数据

划线、笔记、补充、批注、答题进度、面试记录、运行轨迹与模型密钥都只在本机。公开仓库只保留 `personal/README.md` 与忽略规则。

### 3.2 署名

版权与来源声明使用公开 handle；不写私人账号、邮箱或本地用户名。

### 3.3 内网与运维信息

不发布内网地址、主机名、SSH 指纹、私有域名、LaunchAgent 前缀与部署路径。导出时先替换再扫描；替换规则与禁止模式都在导出脚本里，新增敏感类别时同步补规则。

### 3.4 密钥与凭证

扫描常见的 API key、GitHub token、云厂商 access key 与私钥头。`.env`、`models.keys.json` 与价格缓存默认排除。

## 4. 提交前检查清单

1. 导出脚本扫描 0 命中。
2. 公开仓库 `git grep` 检查旧主机名、内网地址与私人用户名，无命中。
3. 新增文档里的命令与路径能在公开快照里成立，不指向私人仓库。
4. 公开仓库的测试（阅读器 personal 测试、Harness 清单）通过。

## 5. 复现

```bash
node scripts/export-public.mjs --out ../ai-agent-book-public --force
cd ../ai-agent-book-public
git grep -n -i -E "内网地址|主机名|私人账号" || true
```

导出脚本会更新 Harness 清单哈希，并在扫描失败时以非 0 退出。

## 6. 边界

- 导出只做文本脱敏，不处理二进制文件内部内容；新增二进制资料前先确认来源与授权。
- 公开快照不包含私人 Git 历史；发布用单条快照提交，避免历史里残留私人信息。
- 若发现遗漏，先修导出规则，再重跑导出并强推公开仓库。
