# 部署

本仓库支持两种长期运行方式：前台用 `scripts/start.sh` 跑着，或用 macOS LaunchAgent / Linux systemd 让它在登录后自动启动、崩溃后自动重启。两种方式运行的是同一对进程：阅读器在 4321，实验台在 4330，实验台只监听回环地址。

只想装一次试试的话，按 [README](../README.md) 的快速开始或 [AI部署.md](AI部署.md) 走即可；本文讲长期运行。

## 端口

| 端口 | 进程 | 默认监听 | 说明 |
|---|---|---|---|
| 4321 | Astro 阅读器 | `127.0.0.1`（`--lan` 时 `0.0.0.0`） | 浏览器唯一入口，页面、`/__personal`、`/__lab`、`/harness` 都在这里 |
| 4330 | agent-lab | `127.0.0.1` | 只由阅读器反代，不直接对外 |

端口可用 `READER_PORT`、`LAB_PORT` 覆盖；改端口后 `LAB_READER_URL` 要一起改，`start.sh` 会自动传入。

## 方式一：前台

```bash
bash scripts/start.sh            # 只监听 127.0.0.1
bash scripts/start.sh --lan      # 局域网可访问，注意笔记接口也会暴露
READER_PORT=4421 LAB_PORT=4430 bash scripts/start.sh
```

脚本会在前台启动两个进程，任一退出就一起收尾，按 Ctrl-C 停止。日志写在 `run-logs/`。它不会安装依赖，缺 `web-astro/node_modules` 或 `agent-lab/.venv` 时只提示对应命令。

## 方式二：macOS LaunchAgent

把 `<repo>` 换成仓库的绝对路径，`<label>` 换成自己的反向域名标识：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string><label></string>
  <key>ProgramArguments</key>
  <array>
    <string>/bin/bash</string>
    <string><repo>/scripts/start.sh</string>
  </array>
  <key>WorkingDirectory</key><string><repo></string>
  <key>EnvironmentVariables</key>
  <dict>
    <key>PATH</key><string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
    <key>UPDATE_REPO</key><string>Eric-Ma-Q/ai-agent-book</string>
  </dict>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string><repo>/run-logs/launchd.out.log</string>
  <key>StandardErrorPath</key><string><repo>/run-logs/launchd.err.log</string>
</dict>
</plist>
```

```bash
mkdir -p ~/Library/LaunchAgents run-logs
cp <label>.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/<label>.plist
launchctl print gui/$(id -u)/<label>        # 查看状态
launchctl kickstart -k gui/$(id -u)/<label> # 重启
launchctl bootout gui/$(id -u)/<label>      # 停止并卸载
```

用 `launchctl kickstart` 作为更新后的重启命令：`UPDATE_RESTART_CMD='launchctl kickstart -k gui/$(id -u)/<label>'`。PATH 必须包含 `node` 与 `uv`，否则脚本会报找不到命令。

## 方式三：Linux systemd

单用户、无需 root 的做法，`<repo>` 与 `<user>` 换成实际值：

```ini
# ~/.config/systemd/user/ai-agent-book.service
[Unit]
Description=AI Agent reader (unofficial fork)
After=network-online.target

[Service]
Type=simple
WorkingDirectory=<repo>
Environment=PATH=/usr/local/bin:/usr/bin:/bin
Environment=UPDATE_REPO=Eric-Ma-Q/ai-agent-book
ExecStart=/bin/bash <repo>/scripts/start.sh
Restart=on-failure
RestartSec=5
KillMode=control-group

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now ai-agent-book
systemctl --user status ai-agent-book
journalctl --user -u ai-agent-book -f
loginctl enable-linger <user>    # 未登录也保持运行
```

更新后的重启命令写 `UPDATE_RESTART_CMD='systemctl --user restart ai-agent-book'`。需要分别重启两个进程时，把阅读器与实验台拆成两个 unit，实验台用 `uv run python -m agent_lab serve --port 4330`，阅读器用 `npx astro dev --host 127.0.0.1 --port 4321`。

## 环境变量

阅读器侧的变量按这个顺序读取：`scripts/start.sh` 会先读仓库根的 `.env`（可从 `.env.example` 复制），已有环境变量优先；LaunchAgent 也可以写在 `EnvironmentVariables`，systemd 写在 `Environment=` 或 `EnvironmentFile=`。实验台的模型相关配置也可以写在 `agent-lab/.env`（该文件不入库）。

| 变量 | 作用 | 默认 |
|---|---|---|
| `LAB_LLM_BASE_URL` | 模型接口地址，通常以 `/v1` 结尾 | `http://127.0.0.1:8080/v1` |
| `LAB_LLM_API_KEY` | 模型接口密钥 | 空 |
| `LAB_MODEL` | 默认模型 ID | 见 `agent-lab/.env.example` |
| `LAB_READER_URL` | 实验台回调阅读器的地址 | `http://127.0.0.1:4321` |
| `LAB_BOOK_DIR` | 书稿目录 | `<仓库>/book` |
| `LAB_PERSONAL_DIR` | 读者数据目录 | `<仓库>/personal` |
| `LAB_DATA_DIR` | 实验台数据目录 | `<仓库>/personal/lab` |
| `LAB_WEB_PROXY` | 联网工具代理；`off` 强制直连 | 系统代理 |
| `LAB_PRICING_URL`、`LAB_PRICING_TTL_H` | 模型价格目录与缓存时长 | models.dev，24 小时 |
| `LAB_MCP_TOKEN` | MCP 端点口令，少于 16 位视为未启用 | 空 |
| `LAB_MCP_PERSONAL` | `1` 开放读者标注工具，`0` 只读书稿 | `1` |
| `PERSONAL_DIR` | 覆盖读者数据目录（测试用） | `<仓库>/personal` |
| `READER_PORT`、`LAB_PORT` | 端口 | 4321、4330 |
| `UPDATE_REPO` | 更新来源，`owner/repo` 形式；为空则更新中心显示未启用 | 空 |
| `UPDATE_BRANCH` | 更新跟随的分支 | `main` |
| `UPDATE_ADMIN_TOKEN` | 一键更新的管理员 token；不设则读 `personal/update/token` | 文件 |
| `UPDATE_RESTART_CMD` | 更新后的重启命令 | 自动探测，失败则提示手动重启 |
| `ASTRO_BASE` | 部署到子路径时的前缀，仅影响构建 | `/` |

密钥类变量不要写进仓库：`.env`、`personal/lab/models.keys.json` 与 `personal/update/token` 都在忽略列表里。

## 健康检查

```bash
curl -sS http://127.0.0.1:4330/health                  # 实验台
curl -sS http://127.0.0.1:4321/__lab/health            # 阅读器反代是否通
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4321/
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4321/book/chapter1/
```

`/health` 返回 `success: true` 表示实验台进程正常；其中 `data.llm.ok` 表示模型接口是否可达。`llm.ok=false` 不影响阅读与设置页，只影响问答。

## 日志

| 文件 | 内容 |
|---|---|
| `run-logs/reader.out.log`、`reader.err.log` | 阅读器标准输出与错误（含 Astro 编译错误、扩展报错） |
| `run-logs/agent-lab.out.log`、`agent-lab.err.log` | 实验台输出与异常 |
| `run-logs/update.log` | 更新脚本的完整输出 |
| `run-logs/launchd.*.log` | 用 LaunchAgent 时 launchd 自己收集的输出 |

排查顺序：先看 `*-err.log` 末尾二十行，再看 `/health` 与端口占用。日志会一直增长，可以在停服时清空或按需轮转。

## 升级与回滚

升级：

```bash
bash scripts/update.sh            # fetch + merge --ff-only + 按需装依赖 + 重启
```

也可以在设置页「项目更新」里一键更新：先在仓库根 `.env` 写 `UPDATE_REPO=Eric-Ma-Q/ai-agent-book`，再生成 `personal/update/token`（600），重新启动阅读器。

发布新版本时，同步改仓库根的 `VERSION`、提交、打 tag 并建 Release（更新中心从 Release 读说明；没有 Release 时回退 tag）：

```bash
echo 0.2.0 > VERSION
git commit -am "chore: release v0.2.0"
git tag v0.2.0
git push origin main --tags
gh release create v0.2.0 --title v0.2.0 --notes "本次更新说明"
```

更新中心假设 `git remote origin` 与 `UPDATE_REPO` 指向同一个仓库：检查走 GitHub API，拉取走 `origin`。如果你用的是镜像或多远端，请把 `origin` 指到发布仓库，或只用命令行更新。

更新只做 fast-forward：工作区有已跟踪改动、或本地提交与上游分叉时会中止，不会覆盖你的修改。依赖只在 `package-lock.json` 或 `uv.lock` 变化时重装。`personal/` 下的数据不参与更新。

回滚代码：

```bash
git log --oneline -5              # 找到上一个可用版本
git switch --detach <上一个版本>   # 或 git reset --hard <上一个版本>
cd web-astro && npm ci && cd ../agent-lab && uv sync --frozen
# 重启服务
```

回滚后建议切回分支继续跟随更新。数据不需要回滚：更新过程从不写 `personal/`；如果误删了读者数据，从自己的备份恢复。

## 排障

| 现象 | 通用原因 | 处理 |
|---|---|---|
| 启动即退出，提示找不到 node/uv | PATH 里没有运行时 | 在启动环境里补 PATH（LaunchAgent 的 `EnvironmentVariables`、systemd 的 `Environment`） |
| 提示缺 `node_modules` 或 `.venv` | 依赖没装或换过机器 | `cd web-astro && npm ci`、`cd agent-lab && uv sync --frozen` |
| 4321 或 4330 被占用 | 上次的进程还在，或别的程序占了端口 | `lsof -nP -iTCP:4321 -sTCP:LISTEN`；换端口或停掉占用进程 |
| 首页 200，`/__lab/health` 502 | 实验台没起或崩了 | 看 `agent-lab.err.log`；单独 `uv run python -m agent_lab serve --port 4330` 验证 |
| `/settings/`、`/harness/`、`/lab/` 404 | 用了 `npm run build` 的静态产物 | 这些页面只在 dev 模式存在，用 `scripts/start.sh` 启动 |
| 局域网打不开 | 默认只监听回环地址 | `bash scripts/start.sh --lan`，并检查防火墙放行 4321 |
| 问答报鉴权失败 | 接口地址或密钥不对 | `/settings/` 测试连接；确认 `LAB_LLM_BASE_URL` 以 `/v1` 结尾 |
| 问答很慢或超预算 | 上下文与轮数过大，或模型本身慢 | 在实验台调低最大轮数/总 token，换更快的模型 |
| 更新显示「未启用」 | 没有 `UPDATE_REPO` 或管理员 token | 设置变量并生成 `personal/update/token`（权限 600） |
| 一键更新返回 401 | token 与服务器不一致 | 重新读取或生成 token，在页面重新输入 |
| 更新中止，提示工作区有改动 | 更新只允许 fast-forward | 提交或还原已跟踪文件的改动后重试 |
| 更新后页面没变化 | 重启命令没生效 | 手动重启；设置 `UPDATE_RESTART_CMD` |
| MCP 返回 503 | `LAB_MCP_TOKEN` 为空或太短 | 设置至少 16 位口令后重启 |
| MCP 返回 401 | 没带 `Authorization: Bearer` | 客户端补上请求头；不要把 token 放在 URL 里 |
| 笔记写入失败 | 磁盘满、权限不对，或数据目录被覆盖 | 检查 `personal/` 权限与磁盘空间；看 `reader.err.log` |
| 批注没显示 | `quote` 与原文对不上 | 改批注文件的 `quote`/`context`；控制台会给出跳过条数 |

更多部署前的准备与验证命令见 [AI部署.md](AI部署.md)，组件与请求流见 [架构.md](架构.md)。
