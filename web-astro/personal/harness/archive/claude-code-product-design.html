产品拆解 · Claude Code · 2026-10

Claude Code 的产品设计把「终端里的 Agent」做成一套操作系统

2025 年 2 月它还是一个「有限研究预览」的命令行工具；2026 年 10 月的 v2.1.305 已经有 46 个工具条目、33 个 hook 事件、6 种权限模式、9 个运行界面，年化收入超过 25 亿美元。 核心闭源，但 Agent SDK（MIT）与 sandbox-runtime（Apache-2.0）可以下载、阅读、跑测试。 本文用官方文档、版本数据和这两份开源代码，复原它的产品结构：它到底在卖什么，哪些是设计取舍，哪些只是实现细节。

一句话结论

Claude Code 卖的不是模型能力，而是一套把「不确定的模型」变成「可交付工作」的 harness：工具给行动，上下文给注意力，权限给信任，多界面给场景。

模型会持续变强，harness 的每一层假设都会过期；因此它的产品设计不是「加功能」，而是不断把该由模型决定的事交还模型，把该由系统保证的事（权限、回退、成本）留给自己。[28]

  • 产品本体是 harness，不是模型。官方定义里，Claude Code 是「模型外面那层提供工具、管理上下文的东西」；模型换代时，这层要跟着改。[2]
  • 设计主轴是「减少打断」。从逐次审批走到「默认 auto + 系统级沙箱 + 可回退检查点」：不可逆的动作才拦，可逆的让它跑。[4][6][26]
  • 先做可组合的扩展点，再做产品化。hooks 先作为通用事件总线存在，后来才长出「mods」这种直接改终端界面的插件；subagents 先解决上下文隔离，后来才变成 agent teams。[7][9]
  • 内核只有一套，表面在扩散。同一个循环、同一套工具与权限规则，跑在终端、IDE、桌面、浏览器、手机、Slack、CI 与云会话里。[13]
  • 开源的是骨架，闭源的是编排。SDK 暴露 49 个选项，沙箱 49 个 TypeScript 文件可读；主循环、提示词、权限分类器、云端服务不公开。[22][23][21]

01时间线：18 个月，四次形态变化

它没有一次性设计成现在这样，而是每半年换一次形态。版本节奏本身就是一个产品信号：550 次发布意味着团队在用「每天可发版」的方式做 agent，而不是按季度交付一个大版本。[20]

  1. 2025-02-24
    研究预览：一个会自己跑命令的终端工具随 Claude 3.7 Sonnet 发布，「有限研究预览」，能读代码、改文件、跑测试、提交并推送 GitHub。定位是「研究开发者怎么用 Claude 写代码」。[24]
  2. 2025-05-22
    正式可用：从实验品变成产品随 Claude 4 开放给所有用户，开始进入团队采购视野。[25]
  3. 2025-09-29
    2.0：把「长任务」当成核心场景原生 VS Code 扩展、检查点（Esc 两次回退）、子代理、hooks、后台任务；Claude Code SDK 更名为 Claude Agent SDK。[26]
  4. 2025-10-20
    上云：浏览器里开并行会话Claude Code on the web 研究预览，每个任务跑在隔离沙箱里，自动开 PR；同期上线 iOS。[32]
  5. 2026-01
    外溢：从写代码扩到知识工作Anthropic 单月发布 30 多个产品与功能，Cowork 把 Claude Code 的工程能力带进更广的知识工作。[27]
  6. 2026-02-12
    商业化验证：25 亿美元年化Series G 披露 Claude Code 年化收入超过 25 亿美元、企业收入过半、商业订阅自年初翻两番。[27]
  7. 2026-10
    平台化：默认 auto、mods、多代理v2.1.305；auto 成为内置默认权限模式（v2.1.283 起），mods 允许插件直接绘制终端界面，agent teams 仍处实验阶段。[19][4][9][35]
读法

这四次变化分别对应四个产品命题：能不能自主行动（2025 上半年）→ 敢不敢交给它长任务（2.0）→ 能不能离开这台机器（云端与移动）→ 能不能被组织规模化采用（权限、计费、控制面）。

02定位：三个「不做」定义了它是什么

官方给它的定义很克制：一个住在终端里、能读代码库、改文件、跑命令、处理 git 工作流的 agent。[21] 但更准确的说法在文档里：模型负责推理，Claude Code 是模型外面那层「提供工具、管理上下文」的东西，也就是 agentic harness。[2]

不做模型

模型是上游，产品是 harness

它不训练模型，也不锁死一个模型：会话内可切换，企业可走 Bedrock、Vertex、Foundry 或自建网关。产品价值落在「怎么用模型」而不是「用哪个模型」。[1]

不做 IDE

把 IDE 当宿主，不当对手

VS Code 与 JetBrains 都是扩展：内联 diff、终端会话、文件上下文，会话仍由 CLI 内核驱动。桌面端补的是「并行会话 + 视觉审查」，不是编辑器。[13][26]

不做一次性生成

做长会话与可恢复状态

检查点、会话恢复与分支、压缩、后台任务、云端续跑：假设任务会跨小时、跨设备、被打断。一次性补全的产品不需要这些。[26][36]

做平台

把「怎么用」变成可配置

CLAUDE.md、skills、hooks、subagents、MCP、plugins、mods：同一套能力既能被个人改，也能被组织统一下发。[10]

定位一句话

给已经在终端里工作的人，一个能自己读代码、改代码、验证结果的同事；先从一条命令开始，再逐步长成团队的基础设施。

它的扩张顺序也印证了这一点：先个人、再团队、再组织；先本地、再云端；先编码、再知识工作。[27]

代价是「边界感」变弱。当它同时是 CLI、IDE 插件、桌面应用、云会话、Slack 机器人、CI 步骤时，用户很难一句话说清「Claude Code 是什么」。产品用「同一个引擎，不同交互密度」来回答这个问题，而不是给每个表面起新名字。[13]

03用户与场景：四类人，四种交互密度

同一个内核被包装成四种工作方式。判断一个界面该不该做，标准不是「能不能跑」，而是「这类用户的交互密度是否匹配」。

角色典型任务首选界面关键机制证据
个人开发者探索代码、修 bug、重构、写测试CLI、VS Code、JetBrainsplan 模式、检查点、/rewind、子代理隔离上下文[4][26]
团队PR 审查、CI 修复、批量维护Code Review、GitHub Actions、Slack多代理审查 + 验证步骤 + 内联评论；不阻断合并[16]
平台 / 安全统一策略、隔离、成本与审计托管设置、网关、分析面板、云会话managed settings、沙箱、OTel 指标、provider 路由[1][6][18]
非工程角色改文案、跑预览、看 diff、做原型Desktop、Web、手机可视化 diff、应用预览、artifacts、computer use[14][27]

谁不适合：要求完全离线、不接受订阅制、需要零数据留存（ZDR）或特定合规配置的组织。文档明确把 Code Review、ultrareview 等能力排除在 ZDR / HIPAA / CMEK 场景之外。[16][17]

产品做对的地方

  • 让同一份配置（CLAUDE.md、MCP、权限）跨本地表面共享，降低切换成本。[13]
  • 把「审查」做成可视化：diff 面板、应用预览、PR 监控，而不是让用户读终端日志。[14]
  • 给非工程角色一个不碰终端的入口，但不另造一套 agent。[27]

仍然存在的摩擦

  • 能力按订阅计划与 provider 切分，读者需要一张对照表才知道自己能用什么。[1]
  • 云端与本地是两套执行模型，迁移靠 --cloud / --teleport 之类的命令，心智负担不低。[13]
  • 多界面意味着同一功能要在多处维护一致性，文档里大量「仅某端可用」的注脚就是代价。

04一次会话的六段：产品把设计放在哪里

agent 产品的体验不是「回答得好不好」，而是六段里每一段有没有替用户省掉一次操作。下面按时间顺序拆，每段给出机制与设计意图。

1 启动预载项目记忆、自动记忆、MCP 工具名、skill 描述
2 输入自然语言、/ 命令、@ 文件、plan 模式
3 循环收集上下文 → 行动 → 验证，反复直到完成
4 干预Esc 打断、消息排队、结构化提问、权限裁决
5 收口diff 审查、/rewind、/goal、Stop hook
6 恢复恢复会话、分支、导出 transcript
1 启动
每轮会话开始时加载：CLAUDE.md（建议 200 行以内）、自动记忆（前 200 行或 25 KB）、MCP 工具名、skill 描述、输出风格与 git 状态快照。设计意图：把「每次都要解释」的东西前置，但给常驻内容设上限。[11][12]
2 输入
斜杠命令与 CLI 旗标是两套入口：本机运行 v2.1.305 的 --help 列出 67 个可见旗标，--permission-mode 给出 6 个取值；plan 模式先出方案再改代码，ExitPlanMode 需要批准。设计意图：把「模糊需求」变成「可批准的计划」。[4][39]
3 循环
模型自己决定何时读文件、何时改、何时跑测试；工具结果回灌，直到它判断完成。设计意图：不把步骤写死在 harness 里，步骤由模型按证据决定。[2]
4 干预
随时 Esc 打断；工作期间可以排队消息；AskUserQuestion 用选项而不是追问；权限请求可按工具与参数规则放行。设计意图：人只在「方向错了」或「有风险」时介入。[3][5]
5 收口
每次用户回合前自动存检查点（保留最近 100 个）；/rewind 可只回退代码、只回退对话或两者；/goal 用独立模型逐轮判定完成条件。设计意图：让「交给它长任务」变成可撤销的决定。[26][33]
6 恢复
会话可命名、恢复、分支；transcript 落盘，可导出。设计意图：任务跨天、跨设备、跨人交接。[36]
最容易被忽略的设计

第 5 段和第 6 段才是「敢用」的来源。大多数同类产品把力气花在第 3 段（循环与工具），但真正让用户把复杂任务交出去的是「错了能退、断了能续」。检查点与恢复不是辅助功能，是产品的前提。[26]

05工具层：45 个工具，一套命名空间

工具不是「功能列表」，而是模型能做的动作集合。文档列出 46 条工具条目（TaskOutput 已于 v2.1.277 移除，在册 45 个），按代理权分成五类：文件、搜索、执行、Web、代码智能，另有编排类工具负责分工与提问。[3]

类别代表工具默认是否询问设计意图
文件Read Write Edit NotebookEdit读不询问；写/改询问读便宜、写昂贵；编辑用「精确替换」而不是整文件重写
搜索Glob Grep LSP不询问先定位再读，减少上下文浪费；LSP 补符号级导航
执行Bash PowerShell Monitor询问一个通用执行器覆盖编译、测试、git、脚本；可被沙箱包住
WebWebFetch WebSearch询问只在需要外部事实时用，避免默认联网
编排Agent SendMessage Task* Workflow AskUserQuestion多数不询问把「分工、等待、提问」也做成工具，让模型自己编排
会话EnterPlanMode EnterWorktree ReportFindings Artifact视工具而定把工作流状态（计划、隔离目录、审查结果）显式化

三条设计规则

  • 一个工具一个动词。不做一个「万能 shell 工具」包办所有事，而是让权限规则、hook matcher、子代理工具清单都能引用同一个工具名。[3]
  • 工具名是稳定接口。权限规则写 Bash(git push *)，hook 匹配 PreToolUse 加 matcher，子代理用 tools: 列表；三处共用一套名字，配置才能复用。[5][7][8]
  • 用模型最熟的原语。Anthropic 明确说 Claude Code 建立在 Bash 与文本编辑器两个工具上：它们不是为 agent 设计的，但模型见得最多、用得最好；把编排逻辑写进代码执行，能让中间结果不进上下文。[28]
一个可核验的收益

官方给出的对照：给 Opus 4.6 自行过滤工具输出的能力后，BrowseComp 准确率从 45.3% 提升到 61.6%；同一套「让模型自己编排」的思路也解释了为什么 Bash 比一堆窄工具更值钱。[28]

工具也会被删。TodoWrite 正被 TaskCreate/Get/List/Update 取代，TaskOutput 直接移除，改成读后台任务的输出文件；Glob/Grep 在 macOS/Linux 上默认不提供。工具集不是越多越好，而是随模型能力与平台差异做减法。[3]

06权限与沙箱：把「问」换成「分层防御」

这是 2026 年最大的产品变化：默认不再逐次询问。v2.1.283 起，终端会话的内置默认权限模式是 auto：工具调用先过规则，再过一个分类器，只有「不可逆、破坏性、指向环境外」的动作才拦。[4][33]

模式不经询问就能做什么适用
default（Manual）只读敏感工作，逐次审查
acceptEdits读、改文件、常见文件系统命令正在审阅的代码迭代
plan读，加分类器批准的只读命令改代码前先摸清结构
auto几乎所有动作，后台安全校验长任务，减少提示疲劳（当前默认）
dontAsk工作目录内读 + 预先批准的工具，其余直接拒绝锁定的 CI 与脚本
bypassPermissions全部仅限隔离容器 / 虚拟机

三层防御，各管一段

第一层 规则

权限模式 + allow / ask / deny

deny 与显式 ask 在分类器之前评估，任何模式都拦得住；allow 规则在 bypassPermissions 下反而无效。[5]

第二层 分类器

auto 模式的安全审查

默认只信任工作目录与当前仓库的 remote；推送到公司组织、写团队云存储桶默认会被拦，除非加进 autoMode.environment。[33]

第三层 系统沙箱

OS 级边界 + 网络代理

Bash、PowerShell、Monitor 及其子进程被包进沙箱：写限工作目录与临时目录，网络默认无直连、只走本机代理的白名单。[6]

兜底

检查点与保护路径

每个用户回合前存快照，可只回退代码；关键路径的删除与受保护路径的写入，任何模式都不自动批准。[26][4]

设计取舍

安全模型从「每次问」转向「默认放行 + 不可逆才拦 + 可回退」。代价是用户必须理解三件事的边界：规则管意图、分类器管风险、沙箱管影响范围。三者组合起来才成立，单独拿走任何一层都会出问题。

沙箱不是「更严的权限」，是另一类东西

权限决定「要不要批准」，沙箱决定「批准之后能碰到什么」。它只覆盖 Shell 命令：内置文件工具、MCP server、hooks、LSP 都在沙箱外，按各自的权限规则走。[6] 实现上，它用的是开源包 @anthropic-ai/sandbox-runtime：macOS 走 Seatbelt，Linux 走 bubblewrap，网络经本机代理逐 host 判定，凭据文件可单独遮蔽。[23]

这套设计解决了什么

  • 长任务不再被几百次确认打断；[4]
  • 误操作可撤销，用户敢把「删文件、改配置」交给它；[26]
  • 企业可以按仓库、域名、云桶声明「可信基础设施」，而不是给人发一张万能白名单。[33]

没解决什么

  • 提示注入仍可能诱导模型做「规则允许但意图错误」的事；官方把防线放在沙箱与最小权限上，而不是「模型不会上当」。[6]
  • 沙箱外的工具（MCP、hooks、LSP）是更大的攻击面，插件即代码。[23]
  • 默认读权限覆盖大部分机器，凭据保护需要显式配置；默认值并不等于「安全默认」。[6]

07上下文工程：把窗口当预算，不当仓库

agent 的能力上限，很大程度是「注意力预算」的上限。Anthropic 的说法是：上下文是有限资源，边际收益递减，token 越多、召回越差（context rot）。产品设计要做的是决定「什么常驻、什么按需、什么丢掉」。[29]

内容何时进入上下文成本控制
CLAUDE.md / AGENTS.md会话启动，目录层级向上加载官方建议 200 行以内；超出拆到 .claude/rules/ 或 skills[11]
自动记忆会话启动只注入前 200 行或 25 KB[12]
MCP 工具名会话启动工具多时启用 tool search，按需加载[3]
skill 描述会话启动只放 YAML 摘要，正文按需读取（渐进披露）[28]
文件内容模型主动读子代理隔离大读取；压缩后最多重读 5 个文件[12]
被调用的 skill 正文调用时压缩后重注入，单个上限 5,000 tokens、总计 25,000[12]

压缩不是「删历史」，是一次有规则的重建

会话接近上限时自动压缩，/compact 可手动触发并指定焦点。压缩后哪些东西回来，文档给了明确清单：系统提示与输出风格继续生效；项目根 CLAUDE.md、无路径规则的 rules、自动记忆从磁盘重新注入；plan 模式写下的计划重新注入；最近改过的 5 个文件重新读取；后台命令与后台子代理继续跑，并提醒模型别重复启动。[12]

设计原则

能重建的就不要常驻，能落盘的就不塞进窗口，能摘要的就不要留原文。这三句话解释了它为什么反复强调「从磁盘重注入」「最多重读 5 个文件」「skill 正文按需加载」。[12]

窗口也在变大，但产品没把宝押在窗口上。部分模型支持 100 万 token 上下文，压缩逻辑不变；prompt caching 把重复前缀缓存起来，/usage 会显示缓存命中率与失效原因。[12][18] 这是很克制的一步：窗口变大只降低压缩频率，不改变「上下文要被管理」这件事；Anthropic 在长任务 harness 的复盘里也把「上下文与验证」列为真正的瓶颈，而不是模型能力。[30]

隔离

子代理是上下文的垃圾桶

研究类子代理在自己的窗口里读几十个文件，只把摘要交回主会话；官方实测在 BrowseComp 上比最佳单代理高 2.8%。[28]

持久化

记忆文件夹比检索系统更有效

给模型一个可读写的记忆目录，让它在任务中自己决定记什么；官方对照里准确率从 60.4% 提升到 67.2%。[28]

08扩展体系：九种入口，按「触发时机」选

Claude Code 的扩展不是插件市场，而是一组按生命周期排布的入口。官方把它们放在一张表里，并用「你遇到什么情况」来决定先加哪个。[10]

入口加载方式常驻成本什么时候用
CLAUDE.md每次会话高（每轮都占）「永远要这样做」的规则
输出风格每次会话，单选中语气、角色、回答格式
Skill描述常驻，正文按需低可复用流程、参考资料、/deploy 这类动作

Plugin / Marketplace打包分发取决于内容跨仓库复用、团队分发

Workflow脚本编排低几十个子代理的批量任务

用「触发信号」而不是「功能清单」教用户扩展

这是整套文档里最像产品设计的一段：不按功能罗列，而按用户已经发生的痛感给建议。[10]

产品洞察

扩展体系真正的门槛不是「能不能写」，而是「知不知道该写哪个」。把九种入口映射到九个可观察的信号，用户不需要理解架构，只需要认出自己的痛。这比任何 plugin 市场都更能提升采用率。

mods 是这条路的终点，也是新起点。它不再是「给模型加提示或工具」，而是运行在 Claude Code 进程内、能绘制面板、替换内置界面、拦截工具调用的插件。内置的 /diff 本身就是用 mod 实现的。[35] 当宿主允许插件重画自己的界面，它就不再只是一个 agent，而是一个可被第三方扩展的运行时。

09多代理：从「隔离上下文」到「组织协作」

四级并行，解决的是四个不同问题。选错的成本很高：子代理便宜但不会商量，团队能商量但按实例计费，工作流能跑几十个但需要脚本，后台会话适合人不在场。

机制上下文协调方式适合成本
Subagent独立窗口，结果回传主代理统一管理大读取、专职研究、并行小任务低（只回摘要）[8]
Agent team各自独立共享任务表 + 邮箱，成员直接对话需要讨论、互相挑战的复杂工作高（每个成员一个实例）[9]
Dynamic workflow每个子代理独立Claude 写脚本编排，返回一个结果几十个并行、批量审计中高（脚本 + 子代理）[10]
Agent view每个后台会话独立人调度，可 peek / attach多任务并行、人不在场按会话计费[34]

关键细节：让并行「可收场」

  • 工具限制。内置 Explore 与 Plan 只给只读工具，Write/Edit 被拒绝；它们启动时还不加载 CLAUDE.md 与 git 快照，为了快和便宜。[8]
  • 文件系统隔离。EnterWorktree 创建独立 git worktree，多个代理改同一个仓库时不互相踩；路径在工作目录外会要求批准。[3]
  • 协调原语是文件。团队的邮箱是 ~/.claude/teams/{team}/inboxes/{agent}.json，任务表在 ~/.claude/tasks/；写入成功才算送达。[9]
  • 可观测性。agent view 用一屏列出「等你输入 / 进行中 / 已完成」，支持偷看与接管，避免人要在十几个终端窗口里找哪个卡住了。[34]
设计教训

并行的瓶颈不在生成，在合并与判断。官方自己把 agent teams 标成实验特性、默认关闭，并提醒「顺序任务、同文件编辑、强依赖场景用单会话更好」。这是一条很少见但诚实的边界说明。[9]

10多界面：执行位置与交互位置解耦

同一个引擎，九种入口。产品没有为每个界面重写一套 agent，而是把「在哪执行」和「在哪交互」拆成两个维度。[13]

界面执行位置交互方式解决什么
CLI本机终端，全功能终端原生工作流、脚本、Agent SDK
VS Code / JetBrains本机编辑器内 diff、终端不离开编辑器看改动
Desktop本机 / 云 / SSH多会话、diff 面板、应用预览视觉审查、并行会话、非终端用户
WebAnthropic 云浏览器长任务、离开电脑也继续
Mobile云 / 本机（Remote Control）手机在路上启动、监控、批准
Slack / Claude Tag云频道里 @从团队对话直接产出 PR
Chrome本机浏览器扩展用已登录的会话测试 Web 应用
CI（Actions / GitLab）Runner事件触发PR 审查、issue 分诊、定时维护
Cloud sessions / Projects云浏览器、API、定时并行、离线、跨仓库协调

解耦带来的自由

  • 在笔记本上开始，在手机上批准，在浏览器里继续看；Remote Control 让执行留在本机，交互搬到任意设备，代码与文件始终不离开自己的电脑。[13][37]
  • 云端会话可以脱离终端跑，断开也继续；回到终端再用 --teleport 接回。[13]
  • 触发器有三种：时间（定时任务）、事件（PR / GitHub）、API（HTTP 调用），同一套配置复用。[38]

解耦的代价

  • 「我的代码在哪里跑」变成必须解释的问题；本地、云端、SSH、远程控制各有前提。[13]
  • 功能按界面和订阅计划切分，能力矩阵复杂到需要专门一页文档。[1]
  • 云端会话与本地会话的状态同步、凭据与网络策略，都是长期维护成本。

收入结构说明了产品结构。2026-02 官方披露：Claude Code 年化收入超过 25 亿美元，较年初翻倍以上；企业收入超过一半，商业订阅翻了两番。[27]

商业洞察

它没有靠「多几个功能」收企业的钱，而是靠「让企业敢放开」。沙箱、托管设置、审计指标、provider 路由、预算上限——这些不提升单次任务质量，但决定一个组织能不能把 agent 铺到几百人。[1]

分发方式的变化也值得注意：从 npm 包改成平台原生二进制，安装脚本一行搞定。对一个每天发版的 agent 来说，「用户能不能在 30 秒内用上最新版」比「包体积小」重要。[21]

12开源边界：哪些能下载、能读、能验证

先给结论：Claude Code 核心不开源。GitHub 仓库的 LICENSE 写的是 “All rights reserved”，仓库里是插件、示例、变更记录与发布元数据，没有 CLI 源码；npm 包只装一个启动器与按平台分发的原生二进制。[21][20]

可读 · MIT

Claude Agent SDK（Python）

8,311 stars；7 个 Python 文件共 4,628 行，其中 types.py 2,901 行，定义了 49 个会话选项与全部消息、hook 类型。它用子进程驱动 CLI，与 Claude Code 共享同一套工具、上下文与权限框架，是理解「harness 暴露什么」最直接的材料。[15][22]

可读 · Apache-2.0

sandbox-runtime（srt）

5,613 stars、49 个 TypeScript 文件；macOS 用 Seatbelt、Linux 用 bubblewrap，网络走本机代理，逐 host 判定；还带凭据遮蔽、TLS 终止与 seccomp。[23]

可读 · 包装层

Agent SDK（TypeScript）

仓库主要是类型与启动包装，真正的 SDK 由 npm 分发；与 Python SDK 共享同一套 CLI 协议。[22]

不可读

主循环、提示词、分类器、云端

系统提示、工具实现、auto 模式分类器、云端沙箱与桌面 UI 都不在开源范围内。任何关于内部实现的断言都只能来自行为观察。[21]

沙箱的架构：一个可复用的安全骨架

sandbox-runtime 把「文件系统 + 网络 + 凭据」三件事拆开做：文件用 OS 原语（Seatbelt / bubblewrap）挂载与拒绝；网络不直接放行，而是让子进程连本机代理，代理逐 host 问一个独立的 decider；凭据可以在文件与进程代理里被替换成占位符，只在允许的域名上注入真值。[23] 这套结构比「给命令加白名单」重得多，但它解决了一个实际问题：命令会 fork、会起子进程、会走 curl，边界必须落在操作系统与网络上。

我们实际验证了什么

下载三个仓库并统计：Python SDK 49 个选项、4,628 行代码；sandbox-runtime 49 个 TypeScript 文件、版本 0.0.81；npm registry 550 条发布时间、首次 2025-02-24；文档 46 条工具、33 个 hook 事件。还下载了 darwin-arm64 原生包在本机运行：--version 返回 2.1.305，--help 列出 67 个可见旗标与 6 种权限模式取值。命令与口径见随页的调研分册。[39][22][23][20]

没有验证：没有可用的 Anthropic 账号与 API key，未做端到端会话；页面里没有把「未运行」写成「已验证」。

护城河的位置因此很清楚：骨架（SDK 接口、沙箱）会逐渐商品化，真正难复制的是编排——系统提示与工具设计、权限分类器、云端调度、多界面体验，以及「每天发一版」的迭代能力。[28]

这些不是 Claude Code 自己写的「原则」，是从它的产品行为里反推出来的。每条都能在文档或开源代码里找到依据，也能直接拿去评审别的 agent 产品。

15风险、反模式与可迁移结论

风险表现产品上的应对
提示注入网页、issue、依赖说明里藏指令，诱导模型外发数据沙箱限制影响范围、最小权限、网络白名单；不假设模型不会上当[6]
权限疲劳用户为了少点确认，直接开 bypass默认 auto + 分类器；把「问」留给不可逆动作[4]
上下文膨胀CLAUDE.md 越写越长、MCP 工具越接越多，注意力被稀释设上限、按需加载、/doctor 体检并建议瘦身[12]
多代理成本并行看起来快，账单和合并冲突一起涨默认关闭 agent teams；worktree 隔离；agent view 可观测[9]
锁定配置、插件、云端流程绑定单一厂商支持多家 provider 与自建网关；配置以文件形式留在仓库[1]
质量证明审查结果看起来专业，但没有基准；官方明确「审查不批准也不阻断合并」把审查当辅助信号，保留人类合并决定[16]

可迁移（6 条）

  • 把「可回退」做成第一版就有的能力，而不是事后补。
  • 用触发信号组织扩展入口，降低用户的学习成本。
  • 给常驻上下文设硬上限，其余按需加载。
  • 权限规则与工具名共用一套命名空间，配置才能复用。
  • 并行先解决隔离（目录 / 分支 / 任务表），再谈加速。
  • 把「执行位置」与「交互位置」解耦，多端才有意义。

不可迁移（4 条）

  • 默认 auto 依赖一个足够强的安全分类器与模型判断力。
  • 1M 上下文与 prompt caching 的经济性来自自家模型与基础设施。
  • 云端沙箱、跨设备控制、审查服务需要大规模基础设施。
  • 「每天发一版」的节奏依赖一支能承受高频发布的团队。
结论

Claude Code 的产品设计可以概括为一句话：用可组合的扩展覆盖长尾，用分层防御换取自主，用可恢复状态换取信任。它没有试图让模型「更听话」，而是让系统在模型不听话时仍然可控。这也是它从工具长成平台的原因。
