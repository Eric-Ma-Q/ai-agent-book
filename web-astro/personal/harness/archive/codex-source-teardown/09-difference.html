差异判断：Codex 与 Claude Code 不在同一个证据层

把 Codex 与 039 的 Claude Code 放在一起，最容易滑向「谁更强」。这一章只做三件事：先说明材料不对称，再按同一用户问题逐行对照，最后把判断限制在四种类型里。大部分机制是共有的；真正的差异集中在协议层、执行层、记忆管线与仓库边界。

30 秒版

  1. 039 是泄露副本，本专题是官方仓库；证据等级不同，不能把「039 没看到」当成「Claude Code 没有」。
  2. 循环、工具、压缩、权限、子 Agent、hooks、项目指令都是共有问题，差别多在实现结构。
  3. 协议层、unified exec、code mode、两阶段记忆与 message board 是本副本更显式的面；只写「这一版新增了」，不写无法证伪的最高级判断。

## When it runs

The pipeline is triggered when a root session starts, and only if:

- the session is not ephemeral
- the memory feature is enabled
- the session is not a sub-agent session
- the state DB is available

03四种判断，四种写法

共有机制

两边都有同类机制，问题相同；写结构差异，不写优劣。例：循环、工具、压缩、权限、子 Agent。

实现差异

问题相同、实现不同；写清换来什么、付出什么。例：Codex 的 unified exec 把 PTY 会话做成一等工具。

本副本可证的新增面

本副本能指到实现、039 材料未见对应实现；只写「这一版新增了」。例：app-server 协议层。

不可验证

不在仓库或材料不足；写清「只能看到什么」。例：App / Cloud / 模型服务的内部行为。

04取舍：可比，但不能比「谁更强」

同问题对照能帮读者理解设计空间；但材料不对称、版本不同、产品边界不同，任何「谁更好」的结论都会超出证据。页面能给的，是一张可复核的差异表和四种判断类型。

换来什么读者能按同一问题比较结构，而不是背功能列表。
付出什么材料与版本不对称；仓库外部分不可验证；差异不等于优劣。

05一张表读完后，记住三件事

  1. 共有机制占多数：循环、工具、压缩、权限、子 Agent、hooks、项目指令，两边都要解决。
  2. 真正的结构差异在协议与执行层：app-server 把多端复用做成产品面；unified exec 把 PTY 会话做成一等工具；code mode 把工具调用变成可编程 cell。
  3. 仓库边界不是产品优劣：App / Cloud / 模型不在仓库，只能标不可验证；不能把「看不到」写成「没有」。在 039 那边同理，不能把「副本缺失」写成「产品没有」。
