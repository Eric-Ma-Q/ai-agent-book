第 04 章 · 把工具暴露做成矩阵

工具系统：直接调用、延迟发现，还是让模型写代码

工具不是「注册得越多越好」。Codex 先把每个工具放进 direct / deferred / code mode / hidden 四个象限，再让模型按模式选择；同时把 shell 做成可复用的 PTY 会话，把编辑做成 apply_patch。产品判断是：工具面要可发现、可预算、可授权，而不是一张越拉越长的函数表。

30 秒版

  1. 同一个工具可以只给直接调用、只给 code mode、延迟发现或完全隐藏，由三个暴露轴组合。
  2. code mode 让模型写 JavaScript 调用嵌套工具；宿主不可用时回退 direct，不是静默失败。
  3. unified exec 把 shell 做成可复用 PTY：64 个进程、1 MiB 输出、10k token 默认预算。
用户问题工具应该直接摊给模型，还是让模型写一段代码来调用？
实现差异

Codex 把「工具暴露」当成一个可计算的矩阵，而不是固定函数表；code mode 是矩阵里的一列，不是替代所有工具。

01四个象限：工具不是只有「有 / 无」

工具注册之后还要决定暴露方式。代码用 direct、deferred、code-mode 三个布尔轴组合出六种状态，其中三种是常见产品形态：直接给模型、延迟发现、只在 code mode 里可见。

codex-rs/core/src/tools/spec_plan.rs307-318 · 三个布尔轴组合出暴露状态
tool.exposure = match (
            exposures.contains(ToolExposures::DIRECT),
            exposures.contains(ToolExposures::DEFERRED),
            exposures.contains(ToolExposures::CODE_MODE),
        ) {
            (false, false, false) => ToolExposure::Hidden,
            (false, false, true) => ToolExposure::CodeModeOnly,
            (true, false, false) => ToolExposure::DirectModelOnly,
            (true, false, true) => ToolExposure::Direct,
            (false, true, false) => ToolExposure::DeferredModelOnly,
            (false, true, true) => ToolExposure::Deferred,
            (true, true, _) => unreachable!("direct and deferred exposure are mutually exclusive"),
暴露模型看到什么适合什么
Direct工具声明直接进请求高频、参数简单、需要模型立刻用
Deferred先只给工具搜索，按需加载工具很多、上下文预算紧
Code mode only只出现在代码执行的嵌套工具里组合调用多、单次调用少
Hidden模型看不到被策略禁用或当前环境不适用

02code mode：把调用写成一段 JavaScript

code mode 的工具声明不是 JSON schema，而是 freeform + Lark grammar；模型输出一段 JavaScript，运行时再把它拆成嵌套工具调用。这样可以把「先查、再改、再跑」写成一个 cell，而不是多轮函数调用。

codex-rs/core/src/tools/mod.rs78-88 · code mode 不可用时回退 direct
pub(crate) fn effective_tool_mode(turn_context: &TurnContext, model_info: &ModelInfo) -> ToolMode {
    let requested_tool_mode = requested_tool_mode(turn_context, model_info);
    if !turn_context.code_mode_available
        && requested_tool_mode == ToolMode::CodeMode
        && !turn_context.config.code_mode.disable_in_process_fallback
    {
        ToolMode::Direct
    } else {
        requested_tool_mode
    }
}
不要把 code mode 写成「默认开启」。features.code_mode 默认关闭；宿主能力在，工具模式仍要由模型元数据或配置选择。

03unified exec：shell 是一个可复用会话

Codex 的 shell 工具不是「每次起一个进程、收完输出就结束」。它支持 PTY、yield 时间、超时、最大输出和后续 write_stdin；进程可以复用，且有明确上限。

04编辑与发现：apply_patch、tool search

文件编辑走结构化 patch，而不是让模型自由写文件；工具很多时走 tool search，先发现再加载。两者都在解决同一个问题：把「模型能做什么」限制在可审计的动作里。

能力机制产品含义
文件编辑apply_patch 工具 + 变更追踪可审查、可回滚，不鼓励直接覆盖
工具发现tool search + deferred exposure工具面可以很大，但不必全进上下文
进程复用unified exec + write_stdin长命令、交互式命令不必反复起进程
输出预算单工具 10k token / 1 MiB 上限防止一次命令吃光上下文
这些机制在 039 里也有同类问题（工具池、结果预算、工具搜索）。不要把「Codex 有 code mode」写成「只有 Codex 有」，只能写「本副本把暴露矩阵与 code mode 做得更显式」。

05取舍：灵活的工具面，更复杂的发现与授权

暴露矩阵让同一个工具可以按模型、场景、预算切换形态；code mode 让模型写组合逻辑；unified exec 让长命令可交互。代价是工具发现、权限判断、输出截断和回退路径都变多，调试时要同时看「工具是否存在」「是否可见」「是否被策略允许」。

换来什么工具面可裁剪、可延迟加载；长命令与组合调用不必拆成很多轮。
付出什么模型可能不知道工具存在；code mode 有宿主依赖；PTY 会话带来进程与输出管理成本。
