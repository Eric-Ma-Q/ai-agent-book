第 03 章 · 一次任务怎么开始、怎么续跑

主循环：可替换的任务，统一的 turn

Codex 没有把所有工作塞进一个巨大的循环。它先定义 SessionTask，让普通对话、review、compact、用户 shell 各自实现；再由 RegularTask 在外层循环里反复调用 run_turn，内层处理采样、工具与 follow-up。理解这两层，才能看懂「用户中途插话」为什么不会把一轮打碎。

30 秒版

  1. 普通对话、review、compact、用户 shell 都是 SessionTask；主循环不关心具体任务类型。
  2. run_turn 负责一轮；外层 loop 在还有 pending input 时继续，内层 loop 发请求并执行工具。
  3. steering 走输入队列，优先于 mailbox；它不是「打断后重开」，而是把新输入接进当前 turn。
用户问题一次任务从哪里开始，什么时候算结束，用户中途插话又落在哪一层？
共有机制

问题与 039 同类：都要有可中断、可续跑的 agent 循环。Codex 的差异在结构：任务可插拔，turn 循环统一。

01先定义任务，再定义循环

SessionTask 只有三个动作：声明任务类型、给 tracing 名称、执行并返回结果。普通对话、review、compact、user shell 各写各的 run，session 只负责调度与取消。

codex-rs/core/src/tasks/mod.rs202-208 · 任务抽象只约束 kind / span / run
fn run(
        self: Arc<Self>,
        session: Arc<Session>,
        ctx: Arc<TurnContext>,
        input: Vec<TurnInput>,
        cancellation_token: CancellationToken,
    ) -> impl std::future::Future<Output = SessionTaskResult> + Send;

这种写法的收益是任务可替换；代价是生命周期分散在多个实现里，读代码时必须先确认「当前是哪一种 task」。

02外层循环：还有输入就继续

RegularTask 在外层 loop 里调用 run_turn。如果本轮结束但队列里还有 pending input，它把 next_input 清空后继续，而不是把新输入丢掉或另起一个无关任务。

codex-rs/core/src/tasks/regular.rs150-160 · 外层 loop 只在有 pending input 时续跑
loop {
    let last_agent_message = run_turn(
        Arc::clone(&sess),
        Arc::clone(&ctx),
        next_input,
        &mut mcp_startup_requirements,
        prewarmed_client_session.take(),
        cancellation_token.child_token(),
    )
    .instrument(run_turn_span.clone())
    .await?;

03内层循环：采样与工具

run_turn 先准备上下文、压缩与 MCP 需求，然后进入采样循环；run_sampling_request 里还有一层工具循环。三层各管一件事：任务、turn、工具。

不要写成「一个 loop 跑完所有事」。外层管 follow-up，中层管 turn，内层管采样与工具；三层都可以被取消。

04steering：插话不是重启

输入队列把待处理输入分成 mailbox 与 steer 两类；注释写明 steering 优先。也就是说，用户在模型运行时补一句话，系统会把它作为当前 turn 的下一段输入，而不是先中断再新开一轮。

codex-rs/core/src/session/input_queue.rs88-93 · steering 在排队时优先
/// Steering takes precedence when several kinds of input are pending together.
#[derive(Clone, Copy, Debug, Eq, Ord, PartialEq, PartialOrd)]
pub(crate) enum InputQueueActivity {
    Mailbox,
    Steer,
}
输入落点产品含义
用户新消息steering接着当前任务说，不丢上下文
Agent 间消息mailbox多 Agent 协作，不抢占用户输入
工具输出turn input回灌给模型，继续采样

05取舍：可插拔任务，复杂生命周期

把任务做成 trait，review、compact、shell 可以复用同一套取消与事件流；代价是「一轮」不再是一个函数，读代码要跨任务、turn、sampling 三层。对产品经理来说，这意味着「中断」「续跑」「插话」不是三个 UI 按钮，而是三个生命周期契约。

换来什么任务可替换、可取消、可观测；review / compact 不需要复制主循环。
付出什么生命周期分散，调试要跨层；不同 task 的终止条件不一致，产品文案也很难统一。
