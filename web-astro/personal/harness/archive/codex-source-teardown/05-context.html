第 05 章 · 压缩是产品功能，不是补丁

上下文与记忆：90% 是派生上限，65% 是条件预跑

长任务最怕两件事：上下文突然爆掉，和压缩时用户干等。Codex 把压缩拆成几条路径：模型元数据给出 90% 的派生上限，配置可以更小；异步压缩在 65% 左右预跑，但只在特定开关与 provider 能力下成立。记忆则被放到会话外，做成两阶段离线管线，且默认关闭。

30 秒版

  1. AGENTS.md 发现时从 cwd 向上找项目根，最终排列是 user → thread → 项目根→cwd，不是「从根往下找」。
  2. 90% 是 resolved_context_window 的派生上限，实际取 min(模型元数据的 auto_compact_token_limit, 90%)；不是无条件硬阈值。
  3. 65% 的分母是完整 resolved_context_window，且要 AsyncCompaction、remote compaction V2、未开 TokenBudget 才预跑。
  4. 记忆是会话外两阶段管线，feature 默认关闭；读不到「某个账号已开启」的结论。
用户问题长任务怎样不爆上下文，又怎样让压缩不打断用户？
实现差异

压缩在 Codex 里是产品功能：有派生上限、有后台预跑、有摘要预算；记忆则被移到会话外，做成可关闭的离线管线。

01AGENTS.md：发现向上，排列向下

模块注释把两件事写在一起，容易读混：发现是从 cwd 向上找项目根；最终排列是从项目根到 cwd。代码先向上收集目录，再 reverse()，所以并发探测不会打乱最终顺序。

0290%：派生上限，不是通用硬阈值

auto_compact_token_limit() 先算 resolved_context_window * 9 / 10，再和模型元数据里的 config_limit 取 min。如果配置更小，配置优先；如果配置更大，被 90% 截住。它是一条派生上限，不是「所有模型到 90% 必然压缩」的硬阈值。

codex-rs/protocol/src/openai_models.rs579-590 · 90% 与 config 取 min
pub fn auto_compact_token_limit(&self) -> Option<i64> {
    let context_limit = self
        .resolved_context_window()
        .map(|context_window| (context_window * 9) / 10);
    let config_limit = self.auto_compact_token_limit;
    if let Some(context_limit) = context_limit {
        return Some(
            config_limit.map_or(context_limit, |limit| std::cmp::min(limit, context_limit)),
        );
    }
    config_limit
}

另外还有独立的 full context 上限与 model_auto_compact_token_limit_scope（Total / BodyAfterPrefix），所以「90%」不能脱离 scope 与模型元数据单独引用。

0365%：分母、开关与适用路径

异步压缩的判定是 active_context_tokens * 100 < resolved_context_window * threshold，分母是完整上下文窗口，不是 90% 上限。并且在进入这段之前，已经要求 AsyncCompaction 开启、provider 支持 remote compaction V2、未开 TokenBudget。

04记忆：会话外的两阶段管线

记忆不在主对话里「顺手记一笔」。它由启动任务异步跑两个阶段：Phase 1 从 rollout 抽取结构化记忆，Phase 2 合并到文件工作区，再跑一个受限的 consolidation 子 Agent。feature 默认关闭。

codex-rs/memories/README.md29-38 · 启动时异步跑两阶段
## When it runs

The pipeline is triggered when a root session starts, and only if:

- the session is not ephemeral
- the memory feature is enabled
- the session is not a sub-agent session
- the state DB is available

It runs asynchronously in the background and executes two phases in order: Phase 1, then Phase 2.

读路径还有独立的上下文上限：MemoryContextFragment 把注入文本截到 8,900 bytes，避免记忆把当前请求撑爆。它是「读进来的记忆」的上限，不是记忆库的总大小。

05取舍：更少中断，更多后台与摘要损失

派生上限 + 异步预跑能把压缩从「用户等待」挪到「后台准备」，但摘要一定丢信息，后台请求也会花钱；记忆把上下文搬到会话外，能跨会话复用，却引入抽取质量、保留策略与隐私边界。

换来什么长任务更少被上下文打断；压缩可以提前准备；记忆可跨会话复用。
付出什么摘要损失不可逆；异步压缩有条件与成本；记忆默认关闭，开启后还要治理质量与保留。
