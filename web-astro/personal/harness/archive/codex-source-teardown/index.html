产品功能拆解 · 源码级

一个本地 Agent，怎样把运行时、工具与权限拆成产品层

Codex 的源码价值不在功能数量，而在五个产品选择：运行时与 App Server 分层、工具可编程、权限组合、条件后台压缩、角色与协作生命周期。这份拆解按「用户问题 → 选择 → 用户价值 → 代价」逐条展开，再给可复核的代码行；仓库外的 App、Cloud 与模型服务只标边界，不补内部实现。

01五条产品判断

Codex 的源码价值不在功能数量，而在五个产品选择。每条都按「用户问题 → 选择 → 用户价值 → 代价」写，相关章节可直接跳转。它们不是行业独有，而是这份固定提交里的实现判断；第 09 章再与 039 的 Claude Code 逐条对照。

产品判断用户问题Codex 的选择用户价值代价相关章
运行时与 App Server 分层一个 CLI 怎么同时服务 TUI、exec、桌面、移动与 SDK？core 管运行时，app-server 管 thread / turn 协议；TUI / exec 用 in-process 客户端，桌面 / 移动用 daemon。同一套会话语义复用多端，新增表面不必重写 core 集成。协议兼容、experimental 方法与 daemon 生命周期成为新成本。02 · 08
工具可编程层工具很多时，模型该直接调用，还是写代码组合？direct / deferred / code mode / hidden 暴露矩阵；code mode 让模型写 JavaScript 调用嵌套工具。工具面可按上下文裁剪，组合调用不必拆成很多轮。宿主依赖、工具发现与授权面变大；code mode 不可用时要回退。04
权限组合怎样让 Agent 能干活，又不越过文件、命令与网络边界？approval + sandbox policy + execpolicy + network proxy + reviewer 组合。文件、命令、网络、审批分层治理，规则可审计。组合多、平台后端不一致；用户很难从一句「已允许」推断实际边界。06
条件后台压缩长任务怎样不爆上下文，又不让用户干等？90% 派生上限 + 65% 条件异步预跑 + 20k 摘要上限；65% 只在特定开关与 provider 能力下成立。压缩可以提前准备，长任务更少被打断。摘要损失不可逆；后台请求有成本；条件不满足时仍走前台压缩。05
角色与协作生命周期多 Agent 怎么从「再叫一个模型」变成可管理任务？role + spawn / wait / send / close / resume + message board；V1 默认 6 线程，V2 默认 4 个并发线程（含 root）。并行分工、review 隔离、子 Agent 可等待与回收。成本与协调复杂度上升；V1 / V2 两套上限增加理解成本。07 · 09

02五条判断怎样互相支撑

分层让多端复用；工具矩阵让运行时按场景裁剪能力；权限组合给工具与执行设边界；条件压缩让长任务持续；角色与消息板把并行任务变成可管理对象。五条叠在一起，才是「本地 Agent 产品」，而不是「模型 + 命令行」。
