# 开发流程规范

> 核心原则：先查后做，动页面必动文档。本项目没有后端与数据库，"代码"主要是根目录单文件页面、`research/` 分册和构建脚本。

## 1. 准备阶段（动手前）

- **页面确认**：查 [页面清单](../使用文档/页面清单.md)，确认要改的页面、入口、内容来源；新增页面先定 `index.html` 分组与卡片文案。
- **来源确认**：涉及事实、数字、引语，查 [核心数据位置](./核心数据位置.md) 找到对应 `research/` 分册；新事实必须补来源与日期。
- **复用确认**：查 [已有功能模块梳理](../使用文档/已有功能模块梳理.md)，主题脚本、页面骨架、滚动容器、构建断言能复用就不新写。
- **规范确认**：视觉与交互查 [页面规范](./页面规范.md)；多智能体或长调研任务查 [collab/PROTOCOL.md](../../collab/PROTOCOL.md) 与 [collab/BOARD.md](../../collab/BOARD.md)。
- **专题确认**：有构建脚本、状态机或判分逻辑的页面，按 [业务模块文档模版](./业务模块文档模版.md) 在 `docs/学习专题/` 建草稿；只读型长文不必建。

## 2. 开发阶段（执行）

- **页面**：单文件、离线、无外部依赖；主题、视口、可访问性按页面规范执行。
- **生成页**：只改 `hooks-33/`、`_deck/` 下的源文件并重跑构建，产物不手改。
- **数字**：题量、案例数、页面数变化后，同步 `index.html` 卡片与页内说明。
- **存储**：读者数据只写 localStorage，键带版本后缀；密钥、模型地址走环境变量。
- **调研**：按 `collab/PROTOCOL.md` 的写作规范执行（来源、日期、【推断】标注）。
- **专题文档**：新专题先写内容文档（学什么、不做什么、来源），再写实现文档；不写空模板。

## 3. 交付阶段（收尾）

按变动类型更新文档，并在专题任务清单写出验证方式：

| 变动类型 | 必更新 |
|---|---|
| 新增或下线页面 | `index.html` 卡片与分组、[页面清单](../使用文档/页面清单.md) |
| 新增或下线学习专题 | `docs/学习专题/` 按模板建目录或标状态，更新[学习专题索引](../学习专题/README.md) |
| 页面内容或交互改动 | 页面清单的"最后更新"；有专题文档则同步实现文档 |
| 新增可复用片段或脚本 | [已有功能模块梳理](../使用文档/已有功能模块梳理.md)，按模板书写 |
| 调研分册新增或修订 | [核心数据位置](./核心数据位置.md) 的来源行、引用它的页面 |
| 新增或改名 localStorage 键 | [核心数据位置](./核心数据位置.md) 的"读者数据"一节 |
| 生成页产物更新 | 核对源文件、产物、构建断言三者一致 |
| 优化或修复 | 对应专题文档的优化/修复记录；无专题文档则补建 |

## 4. 验证方式

- **页面**：按 [页面规范](./页面规范.md) 第 7 节验收清单逐项检查，不另立标准。
- **生成页**：构建断言通过（`cd hooks-33 && python3 build.py`）。
- **实验**：`python3 -m unittest discover labs/mini-harness/tests`；`cd labs/selfloop && python3 -m unittest discover -s tests -v`。
- **数字**：页面卡片数、题量、案例数与实际内容逐项核对。

不得用"已完成"代替验证结论；没跑的命令和没做的检查要写明。
