# 学习专题文档编写规范

> 本项目没有后端的"业务模块"。与标准模板的对应关系：**一个业务模块 = 一个学习专题**，通常对应根目录一个 HTML 页面、一组调研分册和/或一个构建脚本。
>
> 只在专题"有构建脚本、状态机、判分逻辑或长期维护需求"时建文档；纯长文页面只维护 [页面清单](../使用文档/页面清单.md)，不为了凑结构建空目录。

## 1. 目录结构

```text
docs/学习专题/NN-名称/
├── README.md        # 入口：状态、入口页面、来源、导航
├── 内容文档.md      # 教什么、给谁看、不做什么、来源与核实
├── 任务清单.md      # 进度：进行中、计划、已完成
├── 实现文档.md      # 页面结构、核心逻辑、数据边界、验证
├── 优化记录/        # YYYY-MM-DD-说明.md
└── 修复记录/        # YYYY-MM-DD-说明.md
```

文件夹名用中文并带编号（如 `01-Hooks33事件`），便于 @ 引用；编号只增不改。下线专题在 README 状态里标"已下线"，不删目录。小专题可只保留内容文档和实现文档，README 至少写明状态与导航。

## 2. 文件模板

### 2.1 README.md

```markdown
# [专题名称]

> [一句话简介]

## 专题状态

| 项目 | 内容 |
| --- | --- |
| 当前状态 | 开发中 / 已发布 / 已下线 / 历史留档 |
| 入口 | [页面文件名](../../对应页面.html)；无则写"无" |
| 主要来源 | [research/xx-分册.md](../../research/xx-分册.md) / 外部一手来源 / 自研方法 |
| 构建方式 | 手写单文件 / `python3 xxx/build.py` |
| 最后更新 | YYYY-MM-DD |

## 文档导航

- [内容文档](./内容文档.md)
- [任务清单](./任务清单.md)
- [实现文档](./实现文档.md)

## 核心内容

1. **内容块** - [一句话说明这一块讲什么]
```

### 2.2 内容文档.md

只写教什么（What）和为什么（Why），不写代码、字段、实现细节。

```markdown
# [专题名称]内容文档

## 一、学习目标
[读者看完能判断或做到什么，避免"了解"这类不可验证的表述]

## 二、目标读者
- **读者**：[已有基础、使用场景]

## 三、知识边界
- [本专题明确不覆盖的内容，以及去哪看]

## 四、来源与核实
- [关键数字、引语、案例的出处；外部来源写日期，推断标【推断】]

## 五、可延展的设想
*(未排期的内容扩充)*
```

### 2.3 任务清单.md

```markdown
# [专题名称]任务清单

## 进行中
- [ ] [任务] - [说明]

## 计划中
- [ ] [任务]

## 已完成
- [x] **[任务组]**：YYYY-MM-DD
  - 修改范围：[涉及文件与页面]
  - 验证方式：[命令、浏览器检查点或题量核对]
  - 结论：[通过 / 留有风险]
```

没有验证方式的任务不得标"已完成"。

### 2.4 实现文档.md

只写页面与脚本的核心逻辑，细节指向源码；不写需求争论和进度。

```markdown
# [专题名称]实现文档

## 一、页面结构
- **页面文件**：[根目录 HTML]
- **样式与脚本**：[内联区块；生成页写模板与构建脚本]
- **主要数据**：[research 分册 / 外部数据 / 页面内置数据]

## 二、核心逻辑
1. **[逻辑点]**：[状态机、判分、筛选、主题或存储的处理流程与关键规则]

## 三、数据边界
- **读取**：[research 分册、外部来源或页面内置数据]
- **写入**：[localStorage 键；无则写"无"]
- **上游**：[依赖的调研分册或脚本]
- **下游**：[被 index 或其他页面引用的情况]
- **项目级约束**：[单文件离线、主题键、375px 等必须遵守的约束]

## 四、交互与配置

| 入口 | 位置 | 作用 | 说明 |
| --- | --- | --- | --- |
| [按钮/快捷键/URL 参数] | [区块或脚本] | [触发什么] | [默认值或边界] |

无接口与后端；如页面不接收参数，本节写"无"。

## 五、验证方式
- **自动化**：[构建断言、unittest 命令；没有则写"未补充"]
- **手工**：[浏览器打开、375px、明暗、控制台检查点]
- **数据**：[localStorage 键与导出结果核对；不涉及写"无"]
```

### 2.5 优化记录 / 修复记录

文件名 `YYYY-MM-DD-简短说明.md`。

```markdown
# [标题]

## 问题
[现象、影响范围、读者可见的后果]

## 原因
[根因，未知写"待确认"]

## 修改
- [涉及文件或区块、关键改动]

## 验证
- [命令、页面检查或数据核对]

## 结论
[已解决 / 部分解决 / 留有风险]
```

## 3. 变更时检查清单

- 是否更新了对应专题的 README 状态与"最后更新"。
- 是否涉及页面清单、调研来源或读者数据键；是则更新 [核心数据位置](./核心数据位置.md)。
- 是否新增可复用片段；是则更新 [已有功能模块梳理](../使用文档/已有功能模块梳理.md)。
- 是否写明验证方式，而不是只写"已完成"。
