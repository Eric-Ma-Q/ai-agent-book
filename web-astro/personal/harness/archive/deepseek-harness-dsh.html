◆先看结论

一句话定位

dsh 是 Agent 的「身体」，不是 Agent 本身。它要让模型这个「灵魂」，住进一个可替换、可观察、可重组的运行框架里。

当前状态

Developer Preview（开发者预览版）。接口和存储格式仍在快速重构，官方明确警告「会有破坏性变更」，不适合直接押生产。

核心赌注

用 Cordis 插件系统把模型、工具、会话、沙箱、存储、UI 全部插件化，最终让「Agent = Model + Harness」。

最大看点

它同时是 DeepSeek V4 系列官方 Agent 基准测试的框架——极简模式（Minimal Mode）就是用来跑 Terminal Bench、NL2Repo 这些榜单的。

读者须知的名字澄清：在学术界，DSH 另有所指——CVPR 2016 的图像检索方法 Deep Supervised Hashing（深度监督哈希），与本项目无关。你在 AI Agent 语境下看到的 DSH，指的就是 DeepSeek Harness。

01Harness 是什么：Agent = 大脑 + 身体

Harness 这个词本意是「马具」——把马的力量套起来为人所用的那套装置。在软件领域它是个老词（测试领域早有 test harness），而在 AI 语境里，它指包在模型外面的那层运行时与执行环境。

DeepSeek 官方把这个定位讲得很清楚：

模型是 Agent 的灵魂。Harness 让 Agent 理解环境、使用工具，并在现实场景中持续工作。 —— DeepSeek Harness 官方介绍

换句话说，可以用一个公式概括：

Agent = 大模型（大脑：思考、推理）
      + Harness（身体：读写文件、执行代码、调用工具、与环境交互）

DSH 并不在乎你跑的是 DeepSeek、Claude、GPT 还是 Qwen——它负责的是怎么把任意模型接进一个能干活的身体里。这使它区别于「又一个 AI 编程工具」：它的野心是成为 Agent 时代的开放运行时，而不是单个产品。

2026 年 8 月 13 日开源当天，项目就冲上了数万 Star；一周后约 11 万，9 月中旬约 16.8 万，截至 2026 年 10 月 2 日，GitHub 上已有约 24.2 万 Star、2.9 万 Fork、两万余次提交——这在 Agent 基础设施类项目里是罕见的开局速度。

02核心设计：一切皆插件，Cordis 内核

DSH 的官方口号是 “Everything is a Plugin”（一切皆插件）。整个系统构建在 Cordis 插件元框架之上——其设计理念来自论文《A Programming Paradigm for Spatiotemporal Composability》（时空可组合性的编程范式）。

在这种架构下，一个 Agent 运行所需的每一块能力都被拆成了可替换的插件：

插件类别负责什么
模型适配器接入 DeepSeek / Claude / GPT / Qwen 等模型，统一对话与多模态接口。想换模型？换插件。
工具文件读写、Shell 终端、文件与网页搜索、浏览器等——Agent 的「手」。
Skills（技能）领域知识与操作规程，按需加载进上下文。
会话与存储追加式会话日志、Session 持久化与迁移。
沙箱隔离执行环境，划定权限边界。
Agent 循环与调度主循环、子智能体、后台任务与队列。
UIWeb 界面、桌面端本身也是一组插件——连界面都可以被替换和扩展。

官方预览版自带的插件包括：终端、Agent 循环、子智能体，以及四个实验性插件：智能体团队（多 Agent 协作，各 Agent 汇总到 Captain 队长节点）、自动授权审查、自动化任务（定时任务，例如「每周五 17:00 整理项目记录生成周报」）、语音输入。

社区插件通过 GitHub 的 dsh-plugin 话题标记来获得曝光，有开发者称插件数量已上千——虽然质量与安全筛选机制尚不成熟，但「可组合」这件事已经被生态初步验证。

创造模式：用对话写插件

最直观的演示来自官方页面：在「创造模式」里对它说「帮我写一个番茄时钟插件」，它会加载 cordis-plugin-development 技能、查询运行时插槽、写代码、调用插件管理器安装并验证——官方演示全程 5 分 24 秒，产出一个可用的悬浮番茄钟插件。这意味着「扩展 Agent 能力」的门槛被压到了「会提需求」的程度。

DSH 的运行形态也很灵活：既可以是桌面应用（提供 macOS Apple 芯片 / Windows 64 位下载），也可以一条命令启动为网页，两种形态共享同一套插件体系。

03四种运行模式

DSH 提供 四种 Preset（预设模式），覆盖从日常使用到模型评测的不同场景：

模式定位默认能力
Standard 完整编程 Agent 文件编辑、Shell、文件/网页搜索、Skills、规划、目标、子代理、工作流
Code 模型写代码编排工具 在 Standard 基础上把工具暴露成 TypeScript SDK，让模型一次性组合多步操作
Minimal 最小化基准环境 只保留持久 Bash 和文件编辑器，专用于模型评测（DeepSeek 官方榜单即用它跑分）
Creator 自定义 Preset 在 Standard 基础上增加运行时检查、插件实验和 Preset 创作向导

其中 Minimal Mode 的战略地位值得单独强调：它不仅是「功能最少」的模式，更是 DeepSeek 官方模型评测的标准环境（详见第 06 节）。

04Trajectory：给 Agent 装上「行车记录仪」

DSH 一个设计上很不一样的点是 Trajectory（执行轨迹）。每次运行中模型看到的所有东西——系统提示、推理过程、工具调用与结果、子代理调度、上下文注入——都会被写入追加式会话日志。你可以在 Trajectory 视图里按来源检查、搜索、分叉、重放。

官方 Web UI 里的开发者轨迹视图提供时长、轮次、调用次数的统计，并能展开每一次工具调用的参数、结果、Schema 与计时（精确到毫秒）。它解决的正是 Agent 调试中最痛苦的问题：

Agent 出错时，难点往往不是「它答错了」，而是「它当时到底看到了什么」。Trajectory 把排查从「猜」变成了「看录像」——这也是社区口碑最好的功能之一。

05版本演进：一个多月的狂奔

从 8 月 13 日开源到 9 月 10 日，发布节奏几乎每两天一次，版本号从 v0.1.0 冲到 v0.1.5-rc.1，破坏兼容性的变更来了好几轮：

版本时间关键变化
v0.1.0-rc.78 月 17 日持久图片附件；Job Panel 子代理任务管理；可配置思考强度
v0.1.0-rc.88 月 19 日多模态原生图片请求；Claude Code / Codex 子代理可作为 Profile Bundle 安装；Windows PTY 持久 PowerShell
v0.1.1-rc.28 月 21 日DeepSeek 适配器改用 Files API 处理图片上传，降低成本
v0.1.2-alpha.28 月 30 日连接失败重试；Agent Preset 切换；Token 用量与耗时显示
v0.1.3-alpha.19 月 4 日任意类型文件上传；代理环境统一；Session 格式升级到 v2（官方同时声明本次存在已知性能回退）
v0.1.5-alpha.19 月 8 日动态系统提示不破坏 KV Cache；右侧 Sidebar 多标签/分栏/预览；Agent API 重构
v0.1.5-rc.19 月 10 日文件交付；Agent Teams 实验包；可继续对话的子代理；Session 格式升级到 V3

值得注意的是中间没有 v0.1.4 线——官方从 0.1.2 直接跳到了 0.1.5，说明功能合流很快，版本号本身还没稳定到「语义化」的节奏。几个值得细看的代码层改动：

  1. 文件上传从「图片专用」变成「任意类型」

    早期附件能力偏科：图片链路完整，但 PDF、CSV、JSON、Markdown 进不来。9 月版本里文件与图片可混排在同一预览区，后台上传带进度和取消，切换会话后上传状态续显，模型按保存路径按需读取。这会直接改变「给 Agent 喂资料」的方式。

  2. 子代理从「发出去就完事」变成可继续对话

    子代理支持消息排队、编辑、删除、单条或全部 Steer 与停止，父任务能更细地控制子代理的推进节奏——这是多 Agent 协作的关键基建。Agent API 也改为显式传递 Agent，避免子代理被误当成根会话参与调度。

  3. Session 格式从 v1 到 v2 再到 V3

    三周内两度升级存储格式：旧日志迁移时保留原文件，但升级后不支持降级读取。这意味着今天写的插件或外部工具，下个月可能就对接不上。

  4. 默认模型切到 DeepSeek 自家型号

    0.1.5-rc.1 起，新会话默认使用 deepseek-flash（DeepSeek-V41-Flash）；配置文件显式指定模型时仍以配置为准。这是 DeepSeek 把自家模型与 Harness 深度绑定的又一个信号。

技术细节上还有一个亮点：动态系统提示的改动做到不破坏 KV Cache——提示词变了但缓存前缀还能复用，这对长会话的推理成本控制很实际。

06为什么 DeepSeek 要自己做 Harness？

最现实的答案是：模型评测需要统一、可复现、可对比的 Agent 框架。在 DeepSeek API 更新日志里（DeepSeek-V4-Flash 2026-07-31、V4.1-Flash 2026-09-10 两次发布说明），你会看到这样一句话：

对于公开基准测试集中的 Code Agent 文本任务，DeepSeek 系列模型使用 DeepSeek Harness 极简模式作为框架进行测试。

也就是说，DeepSeek 系列模型公开的 Code Agent 榜单成绩，是拿 dsh 的 Minimal Mode 跑出来的（第三方使用指南提到，V4-Flash 的 Terminal-Bench 82.7 分即出自该预设）。V4.1-Flash 那条说明还写明了跑分参数：max 档位、top_p=0.95、temperature=1.0。dsh 同时扮演着「公平跑分器」的角色。

但战略意义不止于评测。如果 dsh 能成为业界默认的开放 Harness，DeepSeek 模型就会获得一种「原生优势」——新模型发布时，配套 Harness 已经调好、插件已经适配、评测已经对齐。别人接入其他模型当然可以，但 DeepSeek 自己的组合一定最先跑顺。

这其实是把「模型战争」往上打了一层：从「谁的模型更强」，变成「谁的模型 + 运行时 + 生态更顺」。谁能把 Agent 的「身体」做成标准，谁就能在模型层之外再建一层生态壁垒。

07社区怎么看：好评与冷思考

热度极高，但真实体验比较分化。

肯定的声音集中在三点

  • 「一切皆插件」是真的可换——模型适配器、工具、会话日志、主循环都能插件化，换模型不用重建系统。
  • Trajectory 是复盘神器——Agent 失败的排查从「猜」变成「看录像」。
  • 一条命令就能跑——npx @deepseek-ai/dsh web 启动 Web UI，开箱可用。

谨慎的声音也很一致

  • Developer Preview 不是口号——0.1.3-alpha.1 的 Release Note 直接写明「本次发布存在已知的性能回退」；同步 API 变异步、Session 格式升级，都说明接口还没定型。
  • 生态早期——插件数量增长很快（有作者称已看到 1000+），但质量和筛选机制不成熟，很多能力要自己配。
  • 上手有门槛——「一切皆插件」对开发者是优点，对普通用户是复杂度，理解 Cordis 插件体系需要时间。

一句话总结社区态度：值得研究，不适合无脑押生产。

08四条趋势判断

  1. 从「基础设施演示」快速转向「产品化细节」

    最早的开源版本更像 Agent Runtime 的技术 demo；0.1.2 之后 Web UI 优化明显变多——重试、Token 统计、反馈界面、文件卡片排版。0.1.5 的右侧 Sidebar 支持 Markdown / 代码 / HTML / PDF / 图片预览，几乎是在往 IDE 方向靠。dsh 不只想当底层框架，也在试图直接成为日常开发界面。

  2. 多 Agent 协作是下一个主战场

    Agent Teams 已作为实验性 npm 包发布；子代理支持双向消息、Steer、继续对话；Agent API 重构避免子代理被误当成根会话。这些改动都在为多 Agent 场景铺路。

  3. 「模型无关」和「DeepSeek 原生」长期并行

    插件架构理论上支持任意模型（探测支持自定义 OpenAI 兼容网关与 Anthropic 列表），但默认会话已切到 deepseek-flash，优化也越来越围绕 DeepSeek 模型。这个张力会持续：太封闭会失掉生态，太开放又会弱化自家模型的优势。

  4. 极简模式可能成为事实上的 Agent 评测标准

    只要 DeepSeek 继续用 dsh Minimal Mode 发布模型成绩，其他厂商和研究者就会被「迫」对齐这个环境，否则无法横向比较。久而久之，dsh 可能成为 Agent 评测的默认 harness。

09风险与冷思考

1. 接口稳定性还没有承诺。Session 格式三周两变、Agent API 重构、Inbox API 调整，都发生在几周之内；官方明确说会有破坏性变更。

2. 插件多 ≠ 生态成熟。上千个插件里有多少能稳定运行、有没有安全审核、权限边界怎么管，目前都是空白——给 Agent 装插件，本质上是在给本机放权限。官方也在运行前提醒阅读安全须知（SAFETY 文档）。

3. 产品定位还在摇摆。它到底是「大家的开放 Harness」，还是「DeepSeek 模型的最佳搭档」？两个方向对产品决策的影响完全不同。

4. 与现有工具的竞争关系还不清晰。Claude Code、Codex、Cline、OpenCode 已占住终端和编辑器场景。dsh 的差异化必须建立在「插件化基础设施」上，而不是又多一个聊天窗口。

10上手指南

装好 Node.js 之后，最快的一条路：

# 快速体验 Web UI（默认打开 http://127.0.0.1:3080）
npx @deepseek-ai/dsh web

# 想锁定版本就用 @版本号
npx @deepseek-ai/dsh@0.1.5-rc.1 web

# 从源码安装
git clone https://github.com/deepseek-ai/deepseek-harness
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

也可以直接从官网下载桌面端（macOS Apple 芯片 / Windows 64 位），与 Web 形态共享同一套插件体系。运行前建议先阅读仓库中的安全须知（SAFETY.md）。

适合的场景

  • 研究 Agent 架构——看 Cordis 怎么把运行时拆成插件，学习 Trajectory 的设计。
  • 写插件——给 dsh 写模型适配器、工具或 UI 插件，提前占生态位。
  • 跑模型评测——用 Minimal Mode 跑自己的 Agent 任务，和 DeepSeek 官方成绩对齐。

不建议的场景

  • 直接替代现有生产工具——接口和格式还会变，迁移成本不可控。
  • 让非技术团队日常依赖——插件权限、报错诊断、稳定性都还没准备好。

11写在最后

DeepSeek Harness 最有意思的地方，不是它现在有多好用，而是它试图定义一种 Agent 的组装方式：模型是灵魂，Harness 是身体，插件是器官。谁能把这个「身体」做成标准，谁就能在模型层之外再建一层生态壁垒。

但这一步还早。开发者预览的标签、频繁的破坏性变更、早期插件生态的混乱，都说明它还在寻找最终形态。对普通使用者的务实建议是：把它当作观察 Agent 基础设施演进的最佳样本之一，持续跟踪它的 releases 与社区讨论；想动手的话，从插件开发和 Minimal Mode 评测切入，性价比最高。
