Anthropic 的工作流程转变从“人写代码”到“人管理 Agent”

2025 年 2 月，Claude Code 还只是终端里的研究预览；到 2026 年 10 月，Anthropic 披露： 合并进主库的代码 80% 以上由 Claude 写、每天 3 万次变更、7 个人 5 个月重写版本控制系统、初级技术招聘占比从 27% 降到 9%。 这不是一次工具升级，而是把研发流程的默认执行者换成了 Agent。

一句话结论

Anthropic 把研发流程的默认执行者从人换成了 Agent；人退到目标、约束、验收和担责的位置。

转变的边界不在“生成代码”，而在评审、验证、协调、选题这些人类瓶颈。Anthropic 的特别之处，是它把这些瓶颈也一个个用 Agent 和内部工具重写了。

  • 生产：从“人写、AI 补全”变成“Claude 写、人定正确性”；2025-02 前 Claude 作者占比是低个位数，2026-05 超过 80%。[4]
  • 评审：从 PR 末端的人工 gate，变成“机器先审 + 风险分级人工审批”；实质性评审意见从 16% 升到 54%，回滚比例下降 40% 以上。[3]
  • 基础设施：Git 被 3 万次/天压垮，Anthropic 用 7 个人、5 个月自研 Scion；checkout 从分钟级降到秒级，基础设施占用小 200 倍。[2]
  • 组织：初级技术招聘占比 27%→9%，Agent 工时是人类的 6 倍，meta-work 从 10% 升到 22%；人类注意力成为新瓶颈。[1]
  • 研究：Claude 从“帮忙跑实验”走到“自己设计并跑完开放研究任务”；人保留选题、评分标准和判断。[4]
先校准口径

“90% 的代码由 AI 写”是代码行占比，不是工作量占比。Dario Amodei 在 2025-10 说的是“大多数团队 90%”；Anthropic 2026-06 的官方保守口径是“合并进主库的代码行 80%+”；Claude Code 团队说的是“Claude Code 自身约 90%”。三个数字口径不同，不能混着用。[9][4][3]

01时间线：四个阶段，三年完成切换

Anthropic 自己在《When AI builds itself》里把研发流程分成四段。前两段是“人用 AI”，后两段是“Agent 用人”。[4]

  1. 2021–2023
    人在笔记本上写代码和文档和任何一家科技公司一样：人写、人改、人审，AI 还没有进入生产流程。
  2. 2023–2025
    聊天机器人生成片段，人复制粘贴AI 是“更快的搜索引擎 + 代码补全”，但打字、拼装、验证仍然由人完成。
  3. 2025-02-24
    Claude Code 研究预览Agent 可以在终端里执行多步工程任务；这是“从补全到委托”的转折点。[7]
  4. 2025-08
    内部调查：60% 工作用 Claude，自报 +50%但“可完全委托”只有 0–20%；设计、品味、高风险判断仍留在人手里。[6]
  5. 2025-10-16
    Dario：大多数团队 90% 代码由 AI 写他同时说，人不一定变少，可能更多——去做最难的 10%、去监督一组模型。[9]
  6. 2026-03
    Agent 总工时首次超过人类包含自主 Agent 与员工直管的 Agent；到 8 月，仅员工直管的交互式 Agent 就是人类的 6 倍。[1]
  7. 2026-05
    合并代码 80%+ 由 Claude 写；每天 2,500 次变更这是 Scion 重建前的基线；四个月后，变更量涨了 12 倍。[4][2]
  8. 2026-06
    40 万会话研究：人做 70% 计划、20% 执行“人决定做什么，Agent 决定怎么做”第一次被大规模量化。[5]
  9. 2026-09
    每天 30,000+ 次变更Git 与 CI 成为新瓶颈，Anthropic 完成向 Scion 的迁移。[2]
  10. 2026-10
    就业报告 + Scion + Code Review GA生产、评审、组织三条线同时公开：这是一次完整的流程重构，不是单点工具。[1][2][3]

03代码生产：从“人打字”到“Agent 打字”

写代码这件事，已经从人的动作变成了 Agent 的动作；人保留的是“什么算对”的定义权。

以前：AI 是补全，不是执行者

2021–2023 年，Anthropic 的研发和普通科技公司没有区别：人在笔记本上写代码、写文档。2023–2025 年，聊天机器人开始生成短代码片段，但人仍要把片段复制进编辑器、拼装、运行、调试。[4]

一个硬指标：2025 年 2 月 Claude Code 研究预览之前，Claude 作者的合并代码占比是“低个位数”。[4]

现在：Claude 写，人验收

到 2026 年 5 月，超过 80% 合并进 Anthropic 主库的代码行由 Claude 作者；Claude Code 团队说，Claude Code 自身约 90% 的代码由 Claude 写。[4][3]

人均产出也随之跳升：2026 年 Q2，典型工程师人均每日合并代码量是 2024 年的 8 倍；以 2025-12 为基线的六个月里，人均 commit 是 5 倍。[4][1]

口径

“8 倍”是代码行数，不是价值。Anthropic 自己提醒：LOC 是不完美的指标，8× 几乎肯定高估了真实生产率。[4]

人的动作：从“写”变成“定义正确性”

2026 年 6 月对约 40 万个 Claude Code 会话的分析显示：典型会话里，人做约 70% 的计划决策（做什么、用什么方案、什么叫完成），但只做约 20% 的执行决策（改哪个文件、写什么代码、跑什么命令）；执行侧约 80% 由 Claude 决定。[5]

Anthropic 的概括是：在工程里，“人给目标，但不再需要给方法。”（"humans supply the goal, but they no longer need to supply the method"）[4]

“如果你让 Claude 写 90% 的代码，通常意味着你仍然需要同样多的软件工程师，甚至更多——因为他们可以去做最难的 10%，或者去监督一组 AI 模型。”

Dario Amodei，Dreamforce，2025-10-16 [9]

一位 Anthropic 员工的说法更直接：“我已经大约 5 个月没有自己写过任何代码了。”[4]

这意味着：“会写代码”本身在贬值，“能把问题定义清楚、能判断输出对不对、能对结果负责”在升值。代码生产从“手工艺”变成“编辑与验收”。

04代码评审：机器先审，人按风险审

评审没有被取消，而是从“人读每一行”变成“人只处理机器判断不了的风险”。这是整个流程里最值得其它公司抄的一段。

以前：评审是路尽头的一道门

写完代码 → 开 PR → 等同事逐行看。评审发生在最后，质量依赖 reviewer 的时间和注意力。当变更量从每天 2,500 涨到 30,000，这种模式直接失效。[3]

现在：六层流水线

1 自验证先给 Claude 测试、构建或截图，让它展示输出，而不是说“完成了”。
2 AI 评审每个 PR 先由 Claude 审；多个 Agent 找 bug，另一组投票确认。
3 安全审查安全发现未关闭，PR 不能合并。
4 自动检查lint、类型、测试、多平台构建，全部阻塞。
5 人工审批按风险分级：低 0 人、中 1 人、高 2 人；审批只对一个 commit 有效。
6 合并队列合并队列重跑检查；新行为先上 flag，出问题回滚。
人工审批按风险分级 · 手机上可左右滑动
风险例子人工审批
低文档、文案、内部功能、flag 后的增量改动0 人（自动评审与安全检查通过即可）
中普通产品改动；缓存、自动更新、系统提示等敏感区域1 人
高最高风险代码；始终需要两人审的路径2 人

效果：更多评审，更少回滚

内部 PR 获得实质性评审意见的比例从 16% 升到 54%；2026 年 6–9 月，Claude Code 仓库合并的 PR 数翻倍以上，同时回滚比例下降超过 40%。[3]

他们的目标不是“零人工”，而是：大多数 PR 最多一个人类在环（可以是作者本人），且不增加回滚或事故。[3]

“以前，评审是路尽头的一道门：写完代码，开 PR，等同事。现在，评审持续运行，更像写作时的拼写检查。”

Claude Code 团队，2026-10-15 [3]

责任怎么算

  • 谁 prompt，谁负责。Agent 写的 PR，指挥 Agent 的人算作必需 reviewer 之一。
  • 审批只对一个 commit 有效。后续有新 commit，尤其是 Agent 推的或手工解决的 merge，审批要重新给。
  • Agent 的批准不算人的批准。自动评审可以放行低风险改动，但不能填“必须人类”的槽位。[3]

这意味着：评审的核心能力从“读懂代码”变成“设计验证策略、判断风险、承担后果”。reviewer 的时间被集中到真正需要人类判断的地方。

05基础设施：Git 被 3 万次/天压垮，于是自研 Scion

当 Agent 写代码的速度超过人类基础设施的吞吐，瓶颈就从“写”转移到了“合并、构建、CI”。Scion 是这条转移最极端的证据。

以前：Git + 数百个内部 mirror

Anthropic 主分支历史约 100 GB，压缩后的工作副本超过 25 GB；每天约 2,500 万次 code checkout（还不算开发环境、Agent 沙箱和研究任务）；如果朴素地拉取，每天会产生超过 600 PB 的 git 流量。高峰期他们运行了数百个内部 git mirror。[2]

现在：Scion

Scion 的设计前提是“客户端永远在线”：仓库数据分布在服务端，客户端只保留有界缓存，按需取文件；提交、rebase、merge 都在服务端完成；CI 任务甚至可以不做 checkout，直接通过 API 问 diff、blame、history。[2]

规模变化
2026-05 约 2,500 次合并/天 → 2026-09 30,000+ 次/天[2]
团队
7 个人，5 个月，同时建 Scion、评审工具 Antique 和半打相关系统[2]
资源
基础设施 CPU/内存占用比旧 git mirror 方案小 200 倍；checkout 从分钟级降到秒级[2]
代价
不是通用产品，不开源；Anthropic 明确说它不适合替代一般团队的 Git，且需要远超多数企业的内部 AI 预算[2][10]

“写代码不再是瓶颈；现在的瓶颈是所有为人类规模设计的开发基础设施——源码管理、构建、CI。”

Anthropic Engineering，2026-10-13 [2]

更值得注意的是工程师的角色。Scion 团队说，所有参与者现在都认为 Claude 比自己更会写代码；但人仍然提供系统级理解、设计取舍，以及——最常被提到的一件事——对 Claude 说“不”。Agent 有时会为了完成局部任务而违反核心约束，工程师的工作是把它们拉回来。[2]

这意味着：AI 写代码越快，越会暴露下一层的瓶颈。真正的规模化不是“多买几个 Agent”，而是把版本控制、CI、评审、回滚都改造成 Agent 吞吐得下的形态。

06组织与招聘：从“招人写代码”到“招人管理 Agent”

人类从执行者变成管理者，但管理带宽有限；于是“人的注意力”成了新的稀缺资源。

初级岗位收窄，但不是公司收缩

初级技术招聘占全部技术招聘的比例从 2025 年初的 27% 降到 9%；初级员工在技术部门中的占比从 21% 降到 14%。同期，Anthropic 总人数翻了三倍，技术招聘的绝对数量仍在增长——变的是招聘结构，不是总量。[1]

报告把转折点定在 2026 年 1 月：重度使用 Claude 的团队发现，写代码、找 bug、性能工程等工作可以越来越多地交给模型；到 4 月，工程和研究团队开始系统性降低低级岗位的招聘权重。约三分之一的 ML 经理、五分之一的 SWE 经理表示，因为 AI 而减少了招聘。[1]

Agent 工时超过人类，注意力成为瓶颈

  • 2026 年 3 月，包含自主 Agent 在内的总 Agent 工时首次超过人类员工工时；到 8 月，员工直管的交互式 Agent 工时是人类的 6 倍。[1]
  • 交互式会话中约 80% 的时间 Agent 在等人；员工平均要把半个工作周花在阅读 Agent 输出上，非技术部门也一样。[1]
  • “元工作”（meta-work）——写常驻指令、搭监控 dashboard、让一个 Agent 审另一个 Agent——占会话比例从 2025 年秋的 10% 升到 2026 年春的 22%；给 Agent 的书面常驻指令从几百条涨到 8,500 条。[1]
  • 人类会议时间中位数比一年前多 20%，技术 IC 也多 16%。协调、判断、担责仍然要人。[1]

“就像一支 Claude 大军，每一个都在喊我看它。”

Anthropic 工程师，2026 [1]

另一位员工说，人正在“给 Agent 制造瓶颈”（"bottlenecking the agents"）。[1]

招聘标准：从“领域专长”转向“自主性 + 判断力”

2024 年，只有约 5% 的技术岗面试评价、7% 的非技术岗评价提到候选人的 AI 工具经验；到 2026 年，这两个比例分别翻了三倍和四倍。技术岗面试中增幅最大的评价维度是自主性和判断力，领域专长的占比在下降。[1]

Anthropic 还建立了一个“早期预警系统”跟踪受 AI 影响的岗位，并优先做内部再配置；工作满一年的员工，2026 年每月跨部门流动的概率比 2025 年高 50%。[1]

别误读

Dario 说“90% 代码由 AI 写”时，强调的是可能还需要更多工程师；就业报告显示的是初级岗位占比下降、总人数翻三倍。两件事并不矛盾：这是招聘结构上移，不是大规模裁员。[9][1]

这意味着：组织从“金字塔”变成“人 + Agent 舰队”。中间层的执行岗位被压缩，顶层的判断、协调、担责被放大；初级的“练手台阶”变少，是这套模式最尖锐的社会代价。

07研究流程：Agent 跑实验，人选题

研究里“做”的成本在快速下降，“选题、判断、验收”的相对价值在上升。Anthropic 作为 AI 实验室，这条线比写业务代码更能说明问题。

固定目标的实验：3× → 52×

每次发布新模型，Anthropic 都会跑同一个测试：给 Claude 一段训练小模型的代码，让它在不破坏正确性的前提下尽量加速。2025 年 5 月，Claude Opus 4 平均做到 3 倍；2026 年 4 月，Mythos Preview 做到 52 倍。作为参照，熟练人类研究员要 4–8 小时才能到 4 倍。[4]

开放研究：Agent 追回 97% 的差距

2026 年 4 月，Anthropic 让 Agent 做一个开放式的 AI 安全研究：弱模型能否可靠监督强模型。两个人类研究员用一周追回了约 23% 的“弱→强”差距；Agent 用 800 累计小时、约 1.8 万美元算力追回了 97%。[4]

但注意

作者明确加了两条限制：结果没有干净地迁移到生产规模模型；人类仍然选了问题、定了评分标准。Agent 设计的是实验，不是研究方向。[4]

“下一步做什么”的判断

Anthropic 从真实研究会话里挑了 129 个“人类选择有改进空间”的节点，让模型仅凭之前的上下文决定下一步，再由能看到结局的评审判断。Claude 的选择胜过人类的比例，从 2025 年 11 月的 51% 升到 2026 年 4 月的 64%。样本经过筛选，不能当作全面的人类对比，但趋势值得注意。[4]

“现在大致是：人出想法，模型以快一个数量级的速度实现、测试、评估。”

Anthropic 研究员，2026 [4]

这意味着：AI 研发的瓶颈正从“做实验”转向“判断哪个实验值得做、哪个结果可信”。这也是 Anthropic 说“人类判断仍是最后一道防线”的原因。

08非技术部门：写代码能力外溢，边界溶解

当写代码的成本降到接近零，“能描述问题的人”开始自己造工具，技术与非技术的边界被重新划。

销售、法务、财务都在变成 builder

  • 一个销售代表用 Claude 花 3–4 小时搭了自定义 dashboard 和 pipeline；他说这种事以前“完全不在我的能力范围”。[1]
  • 非技术员工的 coding Agent 会话，从 2025 年 8 月的每月 2 次涨到 2026 年 5 月的每月 90 次。[1]
  • 法务用 Claude 扫风险、分诊法律问题、做对外文案的一审；应付账款用 Agent 处理发票；招聘用 Agent 做候选人搜寻和申请跟踪。[1]

Anthropic 在 2025 年的团队用法报告里已经看到这个趋势：律师搭电话树、市场生成数百条广告变体、数据科学家不写 JavaScript 也能做可视化。当时的判断是：Agentic coding 不只是加速传统开发，而是在溶解技术与非技术工作的边界。[8]

这意味着：“会不会写代码”不再是技术部门与非技术部门的分界线；“能不能把问题描述清楚、把结果验对”成为通用能力。对产品经理、运营、法务来说，这是能力杠杆；对初级工程师来说，这是竞争面的扩大。

09机制：为什么这次转变能发生

不是单纯因为模型变强，而是四个条件同时到位，形成一个飞轮。

01 · 可验证性

给 Agent 一个能跑的东西

测试、构建、截图、lint——让 Claude 展示输出，而不是说“完成了”。Boris Cherny 说，这可能是拿到好结果“最重要的一件事”，能把最终效果提升 2–3 倍。[3]

02 · 机器评审

先让机器读，再让人看

每个 PR 先由 Claude 审；多个 Agent 找 bug、投票确认；安全审查可阻塞合并。人只在机器判断不了的风险上花时间。[3]

03 · 回滚

让犯错的成本变低

合并队列、flag、回滚、按 commit 重新审批——错误可以被快速撤销，人才敢把更多执行交给 Agent。[3]

04 · 基础设施

把下一层瓶颈也拆掉

Scion 把 checkout、diff、blame 变成服务端 API；CI 不再需要本地仓库。基础设施吞吐跟上，代码量才能继续涨。[2]

飞轮是这样的：Agent 写得越多 → 评审与基础设施压力越大 → 越要把评审、合并、CI 自动化 → 又能写更多。Anthropic 说，“合并代码的潜在需求几乎是无限的，每移除一个瓶颈，代码量立刻继续上涨”。[2]

关键判断

这不是“给工程师发了个新工具”，而是把整条生产函数改了：执行成本下降，验证与协调成本上升；于是组织把资源从“写”挪到“审、验、管”。

10外部证据与争议：哪些能信，哪些要打折扣

Anthropic 的数据很惊人，但它是单公司、自报、非随机的；外部研究给出了更冷静的对照。

外部论文：任务层增益很大，交付层衰减更快

NBER 2026 年的工作论文《Writing Code vs. Shipping Code》用 50 多万 GitHub 开发者的数据发现：autocomplete、交互式 coding agent、自主 Agent 分别带来 +30%、+180%、+240% 的累计 commit 增长；但到了“项目数”只剩 +80%，到“实际发布”只剩 +30%。[13]

AI 编码工具的生产率增益如何逐级衰减 · 手机上可左右滑动
环节累计增益含义
写代码 / commit+240%（自主 Agent）任务层最快
项目数+80%开始受人的评审、协调限制
实际发布+30%交付层被“弱环节”卡住

作者用“弱环节假说”解释：AI 和人类努力之间有很强的互补性（估计替代弹性 0.23），任务层的巨大增益会被人力瓶颈逐级吃掉。这正好对应 Anthropic 自己说的“人的注意力是瓶颈”。[13]

METR：资深开发者可能高估了自己的提速

METR 2025 年的随机对照实验发现：资深开发者在自己的熟悉代码库上使用早期 AI 工具，完成任务反而慢了 19%，而且自己没意识到。Anthropic 在 2025-12 的报告里主动引用了这项研究，作为“自报生产率”的警告。[14][6]

独立报道：规模被确认，但“可复制性”被质疑

The Register 确认了 Scion 与 3 万次/天的数字，同时提醒：Anthropic 有“充足的资金”来支付这种 token 开销，Scion 不开源、也不适合一般团队。[10] IBTimes 和 36Kr 对就业报告做了独立整理，重点同样落在“初级岗位收缩、Agent 工时 6 倍、人类注意力成为瓶颈”。[11][12]

证据强度

四类证据的强项与弱项 · 手机上可左右滑动
证据强在哪弱在哪
Anthropic 内部数据细、连续、有 192 vs 74 的 adopt / non-adopt 对照自报、单公司、adoption 非随机；质量指标有限[1]

最重要的限制

90% 是代码行占比，不是工作量占比，也不是“90% 的人可以消失”。计划、评审、事故处理、跨团队协调、选题仍然大量由人做；Anthropic 同期总人数还翻了三倍。把单公司数据外推成“全行业初级岗位消失”，证据不够。[1][4]

11可迁移 / 不可迁移：其它公司能抄什么

能抄的是“验证与评审的流程设计”，抄不了的是“无限预算 + 自研基础设施 + 单公司数据”。

可以抄

  • 先给 Agent 可验证的闭环：测试、构建、截图、lint。没有验证，就不要谈自主。
  • 机器先审，人按风险审：低风险自动放行，中风险一人，高风险两人；审批绑定 commit。
  • 把回滚当基础设施：flag、合并队列、快速撤销；错误便宜，才敢放权。
  • 度量人类时间，而不只是代码量：审批次数、等待时间、回滚率、事故率。
  • 把评审当流水线，而不是一道门：在 PR 之前就开始验证，在合并之后继续监控。

抄不了 / 别硬抄

  • Scion 级的基础设施：7 人 5 个月的前提是极强的工程能力与预算；多数团队用托管 Git + 更好的 CI 就够。
  • 无上限的 token 预算：这依赖大量内部 AI 预算与专用基础设施；The Register 也强调其资金优势。[2][10]
  • 单公司自报数据：不能把 Anthropic 的 80% 当成自己的目标；起点、代码库、任务类型都不同。
  • 初级招聘结构：这是 Anthropic 在高速增长、极度依赖 AI 的特定情境下的选择，不是普适的组织模板。

给普通团队的三步

  1. 先选“可验证”的任务：测试覆盖好、反馈快、回滚容易的模块，先让 Agent 端到端跑通。
  2. 再改评审：上机器评审、风险分级、按 commit 审批；用回滚率和事故率做护栏，而不是用“人有没有逐行读”。
  3. 最后改基础设施：当变更量真的把 CI / Git 压垮时，再考虑优化 checkout、缓存、合并队列；不要一开始就自研版本控制。

12结论：三个判断

  1. 转变的本质是“执行”与“判断”分离。Agent 接管执行，人保留目标、约束、验收和担责；代码生产从手工艺变成编辑与验收。
  2. 瓶颈没有消失，只是转移了。从“写代码”转到“评审、验证、协调、选题”；人类注意力成为新的稀缺资源，meta-work 是应对方式，也是新的负担。
  3. 90% 是代码量指标，不是组织指标。真正的变化在评审流程、招聘结构、研究选题和基础设施；只看“AI 写了多少代码”，会错过这场转变最重要的部分。
一句话

以前是“人用 AI 写代码”，现在是“人经营一支 Agent 劳动力”。Anthropic 的案例之所以值得看，不是因为它证明了 AI 会取代工程师，而是因为它把“人到底还负责什么”这个问题，用真实数据摆到了桌面上。
