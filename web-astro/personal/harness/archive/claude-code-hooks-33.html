迁移之夜：33 个 Hook
的一次完整值班

把 acme/web-platform 从 JavaScript 迁到 TypeScript strict：凌晨 2 点由 CI 拉起， worktree 隔离，子代理按包并行，agent team 复核；中途上下文告急、模型限流降级、还有人试图改配置关掉监控。 33 个 hook 事件全部真实触发，一个不多、一个不少，且每个事件只使用它被允许的能力。

33hook 事件，全量覆盖
5类执行器：command / http / mcp_tool / prompt / agent
20可干预的事件（阻止 / 改写 / 反馈 / 代替决策）
6个阶段，从 02:00 到 05:00
值班流程 33 个事件 正确性自检 完整配置

01值班流程

横轴是时间，纵轴是同一阶段内的触发频率。颜色只表达一件事：这个事件能不能改变 Claude Code 的走向。 灰色的 9 个事件同样会执行脚本，只是它们的话没人听——这恰好是审计和告警最需要的性质。

可干预（阻止 / 改写 / 反馈 / 代替决策）— 20 个 仅注入或提示（不能阻止）— 4 个 仅观测（只能产生副作用）— 9 个

点击流程图上任意事件，右侧抽屉会展开它的中文名、触发时机、执行器类型和实际配置片段。打开后可用「上一个 / 下一个」沿生命周期连续翻看全部 33 个；支持 Tab 聚焦 + 回车打开，Esc 关闭，也可跳到下方对应卡片。

能不能拦，由事件决定，不由脚本决定 在 Notification 里写 decision: "block" 不会报错，只会被静默丢弃。选错事件比写错逻辑更常见。
事后事件天生没有「拦截」这回事 FileChanged 触发时文件已经改完，DirectoryAdded 触发时目录已经加好。它们不是被削弱，是本来就没有可阻止的对象。
启动阶段一律用 command SessionStart / Setup 触发时 MCP client 尚未就绪，mcp_tool 类型的 hook 会被直接跳过，只留一条 debug log。

0233 个事件逐个落地

每张卡片都是同一套结构：事件名、matcher、执行器类型、这一晚它具体干什么、真实可用的配置片段， 以及最容易踩的那条边界。卡片左侧的色条与流程图一致。

01

冷启动 02:00

CI 拉起任务，把工具链和上次进度准备好。两个事件都发生在「Claude 还没开始思考」之前。

Setup 仅观测
matcherinit typecommand

02:00，CI 用 claude -p --init 拉起任务。这个 hook 装 jscodeshift / ts-morph、预热 pnpm store，并往 CLAUDE_ENV_FILE 写 MIGRATION_RUN_ID。它不能阻断启动，任何退出码都会继续，所以脚本必须自己幂等。

{"matcher": "init", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/setup.mjs",
  "timeout": 300
}]}

无决策权 · 退出码被忽略 · 只能 command（mcp_tool 在 Setup 恒被跳过）

SessionStart 仅注入
matcherstartup|resume typecommand

resume 上一次中断的迁移：把「还剩 5 个包 / 上次失败在 packages/api」注入上下文，并用 watchPaths 注册 .envrc，让后续 FileChanged 有东西可看。只能加信息，不能改启动流程。

{"matcher": "startup|resume", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/resume.mjs"
}]}

仅 additionalContext · 不支持 http/prompt/agent；启动时 MCP 未就绪，故不用 mcp_tool

NOTE 为什么这里只有两个事件

在「Claude 读到第一句话」之前能干预的只有 Setup 和 SessionStart。InstructionsLoaded 其实也在会话启动时触发，但它只做异步审计、还会随懒加载反复出现，所以归到了退场阶段。

02

入场 02:01

一次性输入面：prompt 校验、斜杠命令展开、流式输出脱敏。

UserPromptSubmit 可干预
matcher—（不支持） typecommand

CI 送进来的 prompt 必须带 SPEC- 编号和分支名，否则 exit 2 打回，避免半夜跑错分支。通过后顺手注入当天的 git status 摘要。注意它只能追加上下文，不能替换用户原文。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/require-spec.mjs"
}]}

decision:"block" + hookSpecificOutput.additionalContext · 无 matcher

UserPromptExpansion 可干预
matchermigrate|release typecommand

有人手打 /migrate 时展开成完整任务书并追加团队 checklist；手打 /release 则要求存在 approval 文件，否则拦下。这条专门补 PreToolUse 管不到的「直接敲斜杠命令」路径。

{"matcher": "migrate|release", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/expand-guard.mjs"
}]}

按 command_name 匹配 · 可 block 展开 + 注入上下文

MessageDisplay 可干预
matcher—（不支持） typecommand

迁移日志里混进内部域名和临时 token，流式渲染时逐批打码成 [REDACTED]。只改屏幕显示，transcript 和模型看到的仍是原文——所以它不能当脱敏的唯一防线。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/redact-display.mjs",
  "timeout": 2
}]}

仅 displayContent · 无 matcher · 默认超时 10s，这里压到 2s 免得卡住渲染

03

工具循环 02:02

整晚最热的一段，每个工具调用都会经过。硬闸门、权限代理、失败反馈、批量检查都在这里。

PreToolUse 可干预
matcherBash|Edit|Write typecommand

两个 handler：guard.mjs 拦 rm -rf、git push、改 package-lock.json；normalize-path.mjs 用 updatedInput 把相对路径补成绝对路径再放行。这是整晚最关键的硬闸门（PermissionRequest 也能拒，但管的是权限层）。

{"matcher": "Bash|Edit|Write", "hooks": [
  {"type": "command",
   "command": "node .claude/hooks/guard.mjs"},
  {"type": "command",
   "command": "node .claude/hooks/normalize-path.mjs",
   "if": "Edit(**/*.ts)"}
]}

hookSpecificOutput.permissionDecision allow|deny|ask|defer + updatedInput · if 只在工具事件生效

PermissionRequest 可干预
matcherBash typecommand

夜里没人点确认。这个 hook 代替人决策：只读白名单（git status、ls、cat 日志）直接 allow，git push / npm publish 一律 deny 并写明原因。

{"matcher": "Bash", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/ci-permissions.mjs"
}]}

hookSpecificOutput.decision.behavior allow|deny（可带 updatedInput）· 不支持 agent 类型

PermissionDenied 仅注入
matcherRead|Glob|Grep typecommand

auto 模式偶尔把只读命令也拒了。这个 hook 回 retry: true，告诉模型「这个你可以重试」，省掉一轮人工干预。它不能撤销拒绝，只是给个提示。

{"matcher": "Read|Glob|Grep", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/retry-readonly.mjs"
}]}

仅 hookSpecificOutput.retry · 只在 auto 模式触发 · classifier 无 verdict 时 retry 被忽略

PostToolUse 可干预
matcherEdit|Write typecommand

每次改完 .ts 文件立刻跑 tsc --noEmit 单文件检查，报错就 block——工具已经跑完拦不住，这个 block 只是把编译错误作为 reason 附在结果旁给 Claude 看。同时用 updatedToolOutput 裁掉输出里的绝对路径。

{"matcher": "Edit|Write", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/tsc-check.mjs"
}]}

decision:"block" 只附 reason，不阻止已执行的工具 · hookSpecificOutput.updatedToolOutput · 失败走 PostToolUseFailure

PostToolUseFailure 可干预
matcherBash|Edit typecommand

工具抛错（OOM、超时、MCP error）时记录到 failures.jsonl，并给出纠正提示。注意权限拒绝和参数校验失败不会走到这里，别指望它兜底。

{"matcher": "Bash|Edit", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/on-failure.mjs"
}]}

decision:"block" 只附反馈（工具已失败） · hookSpecificOutput.additionalContext · 不覆盖权限拒绝与校验失败

PostToolBatch 可干预
matcher—（不支持） typecommand

并行改了 12 个文件后只触发一次：统一跑 eslint --fix，把「这批改了哪些文件、还剩几个错」汇总注入。用 PostToolUse 会触发 12 次，既慢又互相打架。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/batch-eslint.mjs",
  "timeout": 120
}]}

无 matcher · 输入带 tool_calls 数组 · 可 decision:block 中断下一步

04

并发面 02:05

子代理、agent team、任务、worktree、MCP 表单——33 个里最容易被忽略的一层。

SubagentStart 仅注入
matchermigrator typecommand

每个包派一个 migrator 子代理，注入该包的规范、依赖边界、以及「不许改 __snapshots__」。不能阻止子代理被创建，只能影响它一开始看到什么。

{"matcher": "migrator", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/subagent-brief.mjs"
}]}

不能 block · 仅 additionalContext · 按 agent type 匹配

SubagentStop 可干预
matchermigrator typeagent

子代理说「迁移完成」时，起一个核查 agent 去读 diff 和测试报告：没跑单测就打回让它继续，迁移不完整也打回。决策格式与 Stop 相同。

{"matcher": "migrator", "hooks": [{
  "type": "agent",
  "prompt": "核对本次迁移：是否覆盖全部导出、单测是否通过、有无遗留 .js。$ARGUMENTS",
  "timeout": 120
}]}

可 block 让子代理继续 · 支持 agent 类型 · 输入含 last_assistant_message

TaskCreated 可干预
matcher—（不支持） typecommand

任务标题必须形如 migrate/，否则直接取消建任务并返回原因，避免半夜冒出一堆叫「fix stuff」的条目。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/task-naming.mjs"
}]}

exit 2 或 decision:block 取消任务 · 无 matcher · continue:false 被忽略

TaskCompleted 可干预
matcher—（不支持） typeprompt

标记完成前用一次模型判断：单测过了吗？CHANGELOG 加了吗？没满足就 block，任务回到进行中。用 prompt 而不是脚本，是因为「是否完成」需要读上下文判断。

{"hooks": [{
  "type": "prompt",
  "prompt": "只有单测通过且 CHANGELOG 有对应条目时才允许完成。$ARGUMENTS"
}]}

可 block 完成 · 支持 prompt 类型 · TaskUpdate 触发时 continue:false 会被忽略

TeammateIdle 可干预
matcher—（不支持） typecommand

reviewer 队友想收工？先看 review.md 在不在、结论填没填。没有就 exit 2 把人留住，防止「团队里没人真正看代码」。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/reviewer-gate.mjs"
}]}

exit 2 阻止 idle · 无 matcher · continue:false 可让队友彻底停下

WorktreeCreate 可干预
matcher—（不支持） typecommand

每个包一个隔离 worktree：从模板 clone、pnpm install --offline、拷一份 .env.local，最后把路径打到 stdout。打印什么路径就用什么，等于接管了默认 git 行为。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/wt-create.mjs",
  "timeout": 180
}]}

stdout 输出路径（或 hookSpecificOutput.worktreePath）· 非零退出即创建失败

WorktreeRemove 可干预
matcher—（不支持） typecommand

收尾删 worktree 前检查有没有未提交改动：有就 exit 1 拒绝删除，把现场留给早上的同事。JSON 输出在这里会被丢弃，只有退出码算数。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/wt-keep.mjs"
}]}

非零退出否决删除 · 无 matcher · JSON 输出被丢弃

Elicitation 可干预
matcherdesign-review typecommand

MCP 的 design-review server 弹出「确认删除旧 .js」表单。夜里没人填，这个 hook 按 dry-run 结果自动 accept——出现风险项则 decline，整个弹窗被跳过。

{"matcher": "design-review", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/form-answer.mjs",
  "timeout": 5
}]}

action accept|decline|cancel + content · 按 MCP server 名匹配 · 仅 exit 0 时生效

ElicitationResult 可干预
matcherdesign-review typecommand

白天有人手动跑时才会走到：校验他填的表单，发现 drop table / 删备份目录之类的选项就 block——把这次回答改成 decline 回给 server，而不是让它生效。注意——hook 自动回答的那条路径不会触发本事件。

{"matcher": "design-review", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/form-check.mjs"
}]}

可观察/改写/block 回答 · 按 MCP server 名匹配 · 自动回答路径不经过这里

05

收口 04:30

决定「能不能停」和「用哪个模型收尾」，以及上下文压缩前后的两个切入点。

Stop 可干预
matcher—（不支持） typecommand

主代理想下班：检查 12 个包的迁移状态和测试结果，还有红的就 block 继续干，并用 additionalContext 给一条「非错误」的提示（比如「剩最后一个包，优先修类型」）。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/stop-gate.mjs",
  "timeout": 60
}]}

decision:"block" + hookSpecificOutput.additionalContext · 无 matcher · 用户中断不触发

StopFailure 仅观测
matcherrate_limit|overloaded typecommand

凌晨 opus 限流，这一轮直接结束。hook 只做两件事：打告警、写下「下轮降级」标记。它没有决策权，改不了错误，也救不回这一轮。

{"matcher": "rate_limit|overloaded", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/on-api-error.mjs"
}]}

无决策权 · 除 terminalSequence 外 JSON 全被丢弃 · 按 error 类型匹配

PreCompact 可干预
matcherauto typecommand

上下文快满了。先把已完成清单、未决问题、worktree 映射写成 checkpoint 落到磁盘，然后 exit 0——故意不 block，夜里压缩失败会把整晚任务卡死。

{"matcher": "auto", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/checkpoint.mjs"
}]}

本可 decision:"block" 阻止压缩，此处刻意不用 · 按 manual|auto 匹配

PostCompact 仅观测
matcherauto typecommand

压缩完成后把摘要写进 metrics.jsonl 和值班 dashboard，方便早上复盘「模型记住了什么」。无决策权，改不了压缩结果。

{"matcher": "auto", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/compact-metrics.mjs"
}]}

无决策权 · systemMessage 与 continue 被丢弃 · 只能做事后处理

PreModelSwitch 可干预
matcherclaude-sonnet.* typecommand

预算紧张，客户端请求切到 sonnet。策略：剩余包数 ≤3 时 allow，否则 deny 保住 opus 的迁移质量。这是少数能直接否决模型切换的地方。

{"matcher": "claude-sonnet.*", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/model-budget.mjs"
}]}

permissionDecision allow|deny|ask 或 decision:block · 按目标模型名匹配

PostModelSwitch 仅注入
matcherclaude-sonnet.* typecommand

真切到 sonnet 之后注入「省钱模式」提示：先跑 codemod，再逐段人工复核。已经换完了，拦不住，只能补充指令。

{"matcher": "claude-sonnet.*", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/model-notes.mjs"
}]}

仅 additionalContext（stdout 纯文本也会作为上下文）· 无法回滚

06

退场 05:00

环境变化、配置审计、通知与归档。大多数只观测，但 CwdChanged 能改变后续环境。

Notification 仅观测
matcherpermission_prompt|idle_prompt typehttp

权限弹窗晾了 6 秒没人管，或以 idle 60 秒：POST 到飞书机器人提醒值班同学。它不能改通知内容、也不能让通知别弹，就是纯转发。

{"matcher": "permission_prompt|idle_prompt", "hooks": [{
  "type": "http",
  "url": "https://ops.internal/hooks/notify",
  "timeout": 5
}]}

无决策权 · systemMessage/continue 被丢弃 · terminalSequence 仍有效

ConfigChange 可干预
matcherproject_settings|local_settings|skills typehttp

有人（或模型自己）想改 .claude/settings.json 关掉 hooks。这个 hook 把变更 POST 给策略服务，未审批就 block。这是防止「AI 把监控关掉」的关键一环。

{"matcher": "project_settings|local_settings|skills", "hooks": [{
  "type": "http",
  "url": "https://policy.internal/hooks/config-change",
  "timeout": 10
}]}

可 decision:"block" · 按配置来源匹配 · 不支持 prompt/agent

InstructionsLoaded 仅观测
matchersession_start|nested_traversal typemcp_tool

审计用：哪条 CLAUDE.md、哪条 rules 进了上下文，调内部 audit server 的 log_instruction 记一笔。异步执行，不阻塞加载，也改不了加载结果。

{"matcher": "session_start|nested_traversal",
 "hooks": [{"type": "mcp_tool", "server": "audit",
  "tool": "log_instruction",
  "input": {"reason": "${load_reason}"}}]}

无决策权 · 异步 · 支持 mcp_tool（此事件允许 command/http/mcp_tool）

CwdChanged 仅观测
matcher—（不支持） typecommand

cd packages/api 时把包级变量（PKG_NAME、DATABASE_URL）写进 CLAUDE_ENV_FILE，后续 Bash 自动带上。它拦不住目录切换，但能改变切换之后的环境。

{"hooks": [{
  "type": "command",
  "command": "node .claude/hooks/reload-pkg-env.mjs"
}]}

无 matcher · 无决策权 · 写入 CLAUDE_ENV_FILE 的变量持续到下次 CwdChanged

DirectoryAdded 仅观测
matcherslash_command typecommand

迁移中发现一个没登记的包 packages/legacy-billing，/add-dir 之后这个 hook 自动跑 pnpm install 并生成包级 CLAUDE.md。目录已经加进去了，拦不了。

{"matcher": "slash_command", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/new-repo.mjs",
  "timeout": 180
}]}

无决策权（已在 hook 前完成）· 按 slash_command|register_repo_root 匹配

FileChanged 仅观测
matcher.envrc|package.json typecommand

文件系统监听，不管是谁改的（Claude、Bash、还是外部进程）。.envrc 变了就重载 direnv，package.json 变了就重装依赖。matcher 同时是监视名单。

{"matcher": ".envrc|package.json", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/watch-reload.mjs"
}]}

matcher 按 | 切成字面文件名做监视列表 · 无决策权 · 拦不住改动本身

SessionEnd 仅观测
matcherlogout|prompt_input_exit|other typecommand

05:00 收工：归档 transcript、上传指标、清理临时目录、给值班群发一条总结。只有 1.5 秒预算，所以真正的上传是丢后台的。

{"matcher": "logout|prompt_input_exit|other", "hooks": [{
  "type": "command",
  "command": "node .claude/hooks/archive-session.mjs"
}]}

无决策权 · 默认 1.5s 共享预算（可放宽至 60s）· 按结束原因匹配

NOTE 退场阶段几乎全是观测点

7 个里 6 个没有决策权。不是设计偷懒：文件已经改完、目录已经加好，此时能做的本来就只有记录、告警和补救。

NOTE 但 CwdChanged 是个例外

它拦不住 cd，却能通过 CLAUDE_ENV_FILE 改写之后所有 Bash 命令的环境变量——观测类事件里唯一具备「延迟生效」能力的一个。

03自检：为什么这 33 条没有用错

这一页不是手写的。事件清单、能力标注、执行器类型全部在构建时对照文档的约束表做断言， 任何一条越界都会让构建失败而不是渲染出一页好看的错误。

  • 33 个事件恰好各出现一次，无重复、无遗漏、无拼写偏差
  • 10 个不支持 matcher 的事件，配置里全部没有出现 matcher 字段
  • 执行器类型全部落在白名单内：12 个事件支持 5 种，PermissionRequest 不支持 agent，18 个事件只支持 command/http/mcp_tool，SessionStart/Setup 只支持 command/mcp_tool
  • if 字段只出现在 5 个工具事件上——其他事件写了 if 将永远不会运行
  • 9 个「无决策权」事件绝不输出决策字段；20 个可干预事件的决策字段与该事件文档逐条对应

不支持 matcher 的 10 个事件 写了 matcher 不会报错，但语义是错的

事件本页配置正确的过滤方式
UserPromptSubmit未配置 matcher ✓没有过滤维度，每个 turn 都跑；条件写进脚本
MessageDisplay未配置 matcher ✓没有过滤维度；用 index / final 跟踪同一条消息
PostToolBatch未配置 matcher ✓没有过滤维度；在脚本里读 tool_calls 自行筛选
TaskCreated未配置 matcher ✓没有过滤维度；在脚本里检查 task_subject
TaskCompleted未配置 matcher ✓没有过滤维度；在脚本里检查 task_id 与测试结果
TeammateIdle未配置 matcher ✓没有过滤维度；在脚本里检查 teammate_name
WorktreeCreate未配置 matcher ✓没有过滤维度，每次创建都触发
WorktreeRemove未配置 matcher ✓没有过滤维度，每次删除都触发
Stop未配置 matcher ✓没有过滤维度，每轮结束都触发
CwdChanged未配置 matcher ✓没有过滤维度，每次 cd 都触发

20 个可干预事件及其决策字段 字段名写错同样会被静默忽略

事件可用的决策字段边界
UserPromptSubmitdecision:"block" + additionalContext只能追加，不能替换用户原文
UserPromptExpansiondecision:"block" + additionalContext只覆盖手打斜杠命令，工具调用走 PreToolUse
MessageDisplayhookSpecificOutput.displayContent只改屏幕；transcript 与模型看到的仍是原文
PreToolUsehookSpecificOutput.permissionDecision allow|deny|ask|defer + updatedInput@ 引用的文件不产生工具调用，不会触发
PermissionRequesthookSpecificOutput.decision.behavior allow|deny（可带 updatedInput）无交互环境下没有决策就默认拒绝；exit 2 不会被当作拒绝
PostToolUsedecision:"block"（仅反馈）+ hookSpecificOutput.updatedToolOutput工具已经执行，block 只是附原因给 Claude 看；失败走 PostToolUseFailure
PostToolUseFailuredecision:"block"（仅反馈）+ additionalContext权限拒绝、schema 校验失败不触发；工具已失败，block 只附反馈
PostToolBatchdecision:"block" + hookSpecificOutput.additionalContext每批只触发一次，没有 matcher
SubagentStopdecision:"block" + hookSpecificOutput.additionalContextClaude Code 内部子代理结束时也会触发
TaskCreatedexit 2 / decision:block（取消任务）continue:false 在此事件被忽略
TaskCompletedexit 2 / continue:falseTaskUpdate 触发时 continue:false 被忽略
TeammateIdleexit 2 / continue:false无 matcher，每次 idle 都触发
WorktreeCreatestdout 路径 / worktreePath非零退出即判定创建失败
WorktreeRemove非零退出否决删除只认退出码，JSON 输出被丢弃
ElicitationhookSpecificOutput.action accept|decline|cancel + content只有 exit 0 时 hookSpecificOutput 才生效
ElicitationResultaction/content 改写 + decision:blockElicitation 自动回答的路径不触发
Stopdecision:"block" + hookSpecificOutput.additionalContext用户主动中断不触发
PreCompactdecision:"block"压缩前唯一的拦截点
PreModelSwitchhookSpecificOutput.permissionDecision allow|deny|ask / decision:block需 v2.1.251+；超时未响应会阻止切换
ConfigChangedecision:"block"policy_settings 来源的变更拦不住；托管设置同步也不经过此事件

执行器类型不是随便挑的 配了不支持的类型 = 静默跳过

支持范围事件数事件
全部 5 种
command / http / mcp_tool / prompt / agent		 12 PermissionDenied、PostToolBatch、PostToolUse、PostToolUseFailure、PreToolUse、Stop、SubagentStop、TaskCompleted、TaskCreated、TeammateIdle、UserPromptExpansion、UserPromptSubmit
4 种
没有 agent		 1 PermissionRequest（配 agent 会被跳过，权限流程照常走）
3 种
command / http / mcp_tool		 18 ConfigChange、CwdChanged、DirectoryAdded、Elicitation、ElicitationResult、FileChanged、InstructionsLoaded、MessageDisplay、Notification、PostCompact、PostModelSwitch、PreCompact、PreModelSwitch、SessionEnd、StopFailure、SubagentStart、WorktreeCreate、WorktreeRemove
2 种
command / mcp_tool		 2 SessionStart、Setup（Setup 的 mcp_tool 恒被跳过；SessionStart 在启动时 MCP 未就绪也会跳过。本案例一律用 command）

七种典型误用 以及它们真实的后果

错误写法实际后果正确做法
在 Notification 里返回 decision:"block"，想拦下通知 字段被丢弃，通知照发，也拿不到任何反馈 只做转发；要改终端提示用 terminalSequence
在 SessionEnd 里 exit 2，想阻止会话退出 无效。会话此时已结束，stderr 只会显示给你看，不会改变退出 只做归档；耗时操作丢后台（共享 1.5s 预算）
给 PostToolBatch 配 "matcher": "Edit" 该事件无 matcher，配置不报错但按全量触发，过滤逻辑失效 删掉 matcher，在脚本里读 tool_calls 自行筛选
在 PreToolUse 里返回 updatedToolOutput，想改工具结果 该字段属于 PostToolUse，此时还没有结果可改 改结果放 PostToolUse；改参数才用 updatedInput
指望 ElicitationResult 再校验一次 Elicitation 的自动回答 自动回答路径直接回给 server，不触发 ElicitationResult 校验必须写在 Elicitation 内部
在 Stop 上写 "if": "Bash(*)" 非工具事件，if 永不匹配，hook 永远不跑 if 只用于 PreToolUse / PostToolUse / PostToolUseFailure / PermissionRequest / PermissionDenied
在 SessionStart 上挂 type:"mcp_tool" 想启动时打点 启动时 MCP client 未就绪，hook 被跳过，只留一条 debug log 改用 type:"command"，或把打点挪到 InstructionsLoaded
