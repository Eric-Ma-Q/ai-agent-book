## 摘要
1. 八种编排模式(orchestrator-worker/流水线/扇出汇总/评审者-执行者/辩论/层级团队/交接/黑板)可用两轴概括:控制权在谁手里 × 上下文怎么流;Anthropic《Building Effective Agents》的五工作流模式是多数产品的"模式底版"。
2. 核实并修正了一处关键数字漂移:中文社区流传的"Anthropic 40% 失败率"是误传,原文 40% 指"工具测试 agent 重写工具描述后后续 agent 完成时间下降约 40%";token 倍数的官方原话是 agent 4×、多 agent 15×(均逐字核对原文)。
3. 受控实验两个方向都有:不控 token 的广度研究任务多 agent +90.2%(Anthropic 内评);等思考 token 预算下单 agent 一致持平或更优(arXiv:2604.02460,斯坦福 2026-04);编排架构带来的方差极大——可分解金融推理 +80.8% vs 顺序规划 −70.0%(arXiv:2512.08296,260 组配置)。
4. MAST(arXiv:2503.13657,NeurIPS 2025 Spotlight)对 7 框架 1,642 条轨迹标注出 3 大类 14 种失败模式,失败集中在"接缝"而非模型;失败轨迹占比 41–86.7%(按框架/任务)。
5. Anthropic 原文自己承认多 agent 不适合编码("需要所有 agent 共享同一上下文、或 agent 间大量依赖的领域不是好选择");Claude Code Agent Teams 官方文档要求"先研究/评审后并行写码、避免同文件"。这构成与 2025-06 复盘 90.2% 数字同页共存的"正方克制"。
6. 并行写同一代码库的业界答案收敛为三层:进程内 git worktree(Claude Code `--worktree` 四条硬隔离检查、Cursor 2.0 八路)、云端一次性环境(Codex best-of-N 4 路、Copilot cloud agent 指派 issue→Actions→草稿 PR、Cursor Cloud Agents/Projects)+ 分支 + diff/PR 汇合点、以及"任务切分避让 + 机械不变量 + 集中验证"的纪律。
7. A2A 与 MCP 的分工在 2026 年定型(官方原话"高度互补"):MCP 垂直(agent→工具)、A2A 水平(agent→agent,不透明委派);A2A 2026-08 加入 Agentic AI Foundation,TSC 含 8 家厂商代表。
8. 通信介质三分法(消息回传/共享文件/黑板任务板)与"产物落盘只回传引用"是 Anthropic 复盘附录性价比最高的处方;黑板状态用结构化格式并规定唯一写者。
9. 最重要的 harness 设计结论:多 agent 是"用 token 买并行广度"的工具,不是"提升智能"的工具;编码 harness 的合理形态是"读取/评审并行 + 写入串行",80% 的工程量花在委派接口、文件系统、验证器三处基础件上,而不是聪明的拓扑上。
