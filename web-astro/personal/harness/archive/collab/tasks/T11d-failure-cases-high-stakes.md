# T11d · AI 产品设计失败案例续集 D：高风险场景里的自动化决策

**模块**：案例库扩充　**类型**：调研写作　**优先级**：中

## 目标
前三批续集（T11a 对话与内容、T11b 默认值与 agent 工具、T11c 专业流程与陪伴）都已交付。本任务收集 **8–9 个**新案例，主题是 **AI / 自动化在高风险场景替人做决定或执行时出事**：自动驾驶与智能驾驶、医疗与保险审核、公共服务与执法。重点看三件事：系统的能力边界怎么向用户和监管说明、出事后信息有没有如实披露、人工复核是真的还是摆设。

每个案例按现有五段式拆解，写成 Markdown；之后由审核者另派任务并入 HTML（T12 正在并入前三批，本批之后再并）。

## 候选清单（从中选 8–9 个，至少 2 个中文案例）
1. Cruise 无人车拖行行人，事后向监管隐瞒完整视频，被吊销加州运营许可并罚款（2023-10 起）
2. Tesla Autopilot / FSD：驾驶员监控不足导致约 200 万辆召回（2023-12），或"Autopilot / FSD"命名被加州 DMV 认定误导——选一个为主
3. 小米 SU7 高速领航辅助驾驶事故与此后智驾宣传规范收紧（2025-03 起，细节与监管口径自行核实）
4. 百度萝卜快跑等国内无人车运营事故或公开争议（时间、地点、官方回应自行核实）
5. UnitedHealth / naviHealth 用 nH Predict 算法拒绝老年人护理理赔被诉（2023-11 起）
6. Epic 脓毒症预警模型外部验证表现远低于宣传（JAMA Internal Medicine，2021）
7. 荷兰育儿补贴丑闻：风险评分算法把大量家庭错判为欺诈，内阁辞职（2021）
8. 澳大利亚 Robodebt 自动化债务追讨，皇家委员会调查（2023）——属"自动化决策"而非生成式 AI，写清楚这一点
9. 人脸识别错误逮捕（如底特律 Robert Williams / Porcha Woodruff 案）与警方使用规则的变化
10. 中文：再找至少 1 例高风险场景的 AI / 自动化决策争议（医疗、医保审核、政务、交通执法等），要有官方通报或当事方公开回应

候选不满足选例标准（缺可靠来源、更偏纯法律或政治问题）可以换掉，换下的写进报告并说明原因；清单外有更好的案例也可以替换，但不能与上面 42 例重复。

## 每个案例的写法（字段与 casebook 一致）
```
### N. <产品>：<一句话标题>
- 公司 · 产品 / 时间（YYYY-MM）/ 失败类型（2–4 字标签，与已有 15 例的标签不重复为佳）
**一句话定性**：…
**产品假设**：团队押注了什么　**成功指标**：用什么判断成功
**时间线**：MM-DD 发布/信号/响应/修复 + 事件（每条带出处）
**最先发现**：谁　**暴露耗时**：…　**止血耗时**：…
**为什么内部没拦住**：3–4 条（基于公开资料的分析标【推断】）
**根因分层**：① 症状 ② 机制 ③ 产品决策 ④ 流程与组织
**止血 / 修复 / 制度化**：各 1–3 条
**做对了什么 / 还欠缺什么**：各 1–2 句
**如果你是这个产品的 PM**：3–5 条可执行做法
**来源**：编号列表，[官方]/[二手] + 标题 + URL + 日期
```

## 文档结构
1. 开头 `> 调研日期 / 方法 / 检索规模 / 对象界定`
2. 横向对比表：案例 | 失败类型 | 谁先发现 | 暴露耗时 | 止血手段 | 最终修在哪一层（与 casebook 同列）
3. 案例详解（按上面字段）
4. 跨案例规律：3–5 条，编号从 K 开始，说明哪些是对原"十条结论"和续集规律 A–J 的补充、哪些与之冲突
5. **对 harness 设计的启示**（3–5 条，例如"能力边界怎么写进界面和日志""人工复核怎样才不是摆设"）
6. 新增上线检查项：5–10 条，不与 casebook 已有 35 项、T11a/b/c 新增的 29 项重复
7. 参考资料

## 必须回答的问题
1. 自动驾驶 / 智能驾驶几个案例里，产品对能力边界的说法（命名、宣传、界面提示）和实际能力差在哪？监管现在怎么约束这种说法？
2. 出事后的信息披露：哪些案例因为隐瞒或迟报让事故升级（如 Cruise）？如实披露和止血速度是什么关系？
3. "人在回路"什么时候是摆设？医疗、保险、福利、执法案例里，人工复核为什么没有拦住算法的错误？
4. 这些高风险场景的失败，和前 42 例的消费级 AI 产品失败相比，有哪些本质不同？
