# 协作协议（ZCode 执行者必读）

> 本项目是一个 **AI Agent Harness 学习库**。分工：
> - **审核者（Claude Code）**：定路线、写任务单、审核、查缺补漏。不直接搜索和编码。
> - **执行者（ZCode）**：按任务单完成检索、写作、编码，交付文件并写报告。
>
> 双方**只通过文件沟通**。每个 ZCode 会话只处理任务单里指定的一个任务。

---

## 1. 目录约定

```
collab/
  PROTOCOL.md      本协议（只读）
  ROADMAP.md       学习路线与缺口清单（只读）
  BOARD.md         任务看板（只读，审核者维护）
  tasks/Txx-*.md   任务单（只读）
  reports/Txx-*.report.md   你写的完成报告
  reviews/Txx-*.review.md   审核意见（只读；返工任务会引用它）
research/          调研 Markdown 交付物
labs/              动手实验代码（如任务要求）
*.html             学习页面（如任务要求）
```

**只能写**：任务单"交付物"一栏列出的文件 + 你自己的报告文件。其他文件（尤其是已有的 html/md、`collab/` 下的只读文件）**不要修改**，除非任务单明确要求。

## 2. 工作流程

1. 完整阅读本协议 + 你的任务单 + 任务单"必读上下文"里列出的文件。
2. 执行任务。需要检索时，**中英文都要搜**，优先一手来源。
3. 写交付物。
4. 按第 5 节自检。
5. 写报告 `collab/reports/<任务编号>.report.md`（第 4 节格式）。**报告是最后一步**，写完报告即视为交付。
6. 在对话中回复一句"Txx 已完成，报告见 collab/reports/…"。

**并发与限流（2026-10-04 新增）**：账户并发额度有限，多个任务同时在跑。
- 子智能体**同一时刻最多 1 个**；更推荐主智能体自己串行检索。
- 遇到"系统繁忙 / 限流 / 执行失败"：等待约 60 秒后重试，最多 3 次；子智能体失败的检索方向必须由你自己补做，不能直接跳过。
- 补做不了的方向，在报告"待决问题"里写明缺了什么。

**不要**：git commit / push；安装全局依赖；删除文件；改动 `.git`、`collab/` 只读文件。
**遇到阻塞**（来源打不开、需求有歧义、需要权限、口径不清）：不要停下来等，也不要为此反复核算，做合理假设继续，并在报告"待决问题"里写明。**报告是交付的必要条件，任何情况下都要写。**

## 3. 写作规范（调研类）

- 中文写作，术语首次出现附英文原文，如"上下文工程（context engineering）"。
- 开头写一段 `> 调研日期 / 方法 / 检索规模 / 对象界定`，风格参照 `research/07-pi-design-philosophy.md`。
- **每条关键事实都要有出处**，格式：`[官方|二手] 内容（YYYY-MM，来源名 URL）`。
  - [官方] = 厂商仓库/文档/官方博客/论文原文；[二手] = 媒体、社区、第三方评测。
  - 没有找到出处的推断，必须标 `【推断】`。**严禁编造 URL、版本号、数字、引语。**
- 数字（benchmark 分数、价格、token 数、star 数）必须带日期和来源；时效敏感信息注明"截至 YYYY-MM"。
- 有争议的点写"正方 / 反方 / 我们的判断"，不要只写一边。
- 每个大节结尾写 **「对 harness 设计的启示」**（3–5 条，可操作）。
- 文末写「参考资料」列表（编号 + 标题 + URL + 日期）。
- 篇幅以任务单为准，统一按**中文正文字数**计（URL、英文原文引用、代码和配置示例不计）；宁可删掉水分也不要凑字数。

## 4. 报告格式（`collab/reports/Txx-*.report.md`）

```markdown
# Txx 完成报告

## 交付物
- 路径 — 一句话说明 — 字数/行数

## 摘要
5–10 条要点：这次学到/产出的最重要内容

## 方法与规模
检索次数、精读来源数、中/英文来源比例、耗时（估）

## 自检结果
逐条回应第 5 节清单，写"通过"或说明问题

## 与已有内容的关系
和仓库已有页面/调研的重复、补充、冲突之处（写具体文件和章节）

## 待决问题 / 未完成项
做了哪些假设；哪些点没查到；建议后续怎么补

STATUS: DONE
```

最后一行必须是 `STATUS: DONE`（任务失败写 `STATUS: BLOCKED` 并说明原因）。审核者靠这一行判断交付。

## 5. 交付前自检清单

- [ ] 任务单"必须回答的问题"逐条有答案（报告里列出对应章节）
- [ ] 所有关键事实有 [官方]/[二手] 标注 + 日期 + URL；无出处推断标了【推断】
- [ ] 随机抽 5 个 URL 确认可访问、内容与引用一致
- [ ] 没有修改交付物之外的文件（`git status` 自查）
- [ ] 报告里提到的"与已有内容的重复 / 冲突"，每条都 grep 过原文确认存在
- [ ] 每个大节有「对 harness 设计的启示」
- [ ] 争议点有正反两面
- [ ] 代码类：能运行，README 写清运行命令，附一次真实运行输出

## 6. 返工

审核者会在 `collab/reviews/Txx-*.review.md` 写意见，并派发返工任务（编号 `Txx-r1`）。返工时**原地修改原交付物**，报告写到 `collab/reports/Txx-r1.report.md`，并在报告中逐条回应审核意见。
