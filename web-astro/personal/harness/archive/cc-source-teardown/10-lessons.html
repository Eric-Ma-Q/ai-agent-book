第 10 章 · 能搬走的东西

结论：十二件能搬走的事，五件搬不走的事

读源码的收益不在「知道它怎么写的」，而在「知道哪些设计换到自己的产品上还成立」。这一章把前面九章压成一张行动清单，并给出八道自测题。

30 秒版

  1. 最值得抄的是「约束」：结果预算、并发标记、权限顺序、压缩分级、中断补齐 —— 它们决定 Agent 是玩具还是工具。
  2. 最不值得抄的是「体量」：389 个界面组件、96 个渲染器文件，是三年迭代的结果，不是起点。
  3. 有五件事依赖 Anthropic 独有的东西（API beta 能力、服务端配置面、内部账号体系），照搬会踩空。
  4. 如果你的 Agent 现在只有「成功 / 失败」两种状态，先补状态机，再谈多 Agent。
  5. 八道自测题可以用来验收团队是否真的读懂了这套设计。

01十二件能搬走的事

#设计为什么有效落地动作
1循环用生成器，终态显式枚举过程可流式、可中断，结局可测试定义 8–10 个终止原因，写进 SDK 契约
2工具契约分槽位新增工具不改 UI、不改权限引擎把 schema / 权限 / 渲染 / 预算拆成独立方法
3结果预算：落盘 + 预览单次输出不再撑爆上下文设单条与单轮两级上限，保留可回读路径
4压缩按代价递增先清可重取的，再摘要不可重取的实现 3 级：清结果 → 折叠 → 摘要
5权限裁决编号化顺序即安全边界，可逐步测试把 deny 放第一步，写 11 步测试
6工具自渲染进度展示与能力同源让每个工具声明「正在干什么」
7并发标记 fail-closed默认不安全，显式声明才并行isConcurrencySafe 默认 false
8中断即补齐消息序列永远合法，不会因半截工具调用崩为每个 tool_use 造合成 tool_result
9子 Agent 只回灌最终文本父级上下文不被过程污染过程消息不回灌，只回最终结论全文
10任务统一模型一套面板管所有后台工作抽出 TaskType / TaskStatus / TaskOutput
11编译期裁剪 + 运行期灰度两层未完成功能不进二进制，已上线功能可急停构建期 flag + 服务端 gate 分开设计
12启动并行预热首字延迟是体感的第一指标钥匙串、配置、能力表并行拉

02五件搬不走的事

依赖为什么搬不走替代方案
API 侧 beta 能力（tool_reference、cache_edits）工具搜索与缓存编辑都建立在这些能力上；第三方网关常直接 400先做本地版：全量 schema + 客户端摘要
服务端配置面（GrowthBook、托管设置、策略）需要一整套后端与合规流程先用本地配置文件，留出同名开关
内部账号体系（USER_TYPE）内外双版本是组织能力，不是代码能力用「实验组」代替「内部版」
终端 React 渲染（389 组件）三年迭代 + 自维护 Ink 分支先做纯文本流式输出，再逐步组件化
swarm 的窗格方案依赖 tmux / iTerm2，跨平台成本高先做进程内子 Agent + 文件邮箱
一句提醒：这份代码是「已经跑了很久的产品的横截面」，不是「从零搭 Agent 的教程」。直接照搬体量，大概率得到一个跑不起来、也改不动的系统。

04八道自测

能答对六道以上，说明这套设计真的读进去了。答案在折叠里。

主循环为什么用 async generator 而不是返回 Promise？
因为一轮里既要流式产出消息、又要允许调用方随时中断，还要把「为什么结束」作为返回值单独传递。Promise 只能一次性 resolve，做不到过程可见与提前收场。
工具结果超过上限时，是截断还是丢弃？
都不是：落盘成文件，模型收到 2KB 预览与文件路径，需要时可以再读。截断会丢信息，丢弃会让模型以为命令没输出。
四段压缩为什么必须按「预算 → snip → microcompact → collapse → autocompact」排序？
因为代价递增、信息损失递增。先清可重取的结果，再折叠，最后才做不可逆摘要。顺序反了会把还要用的细节先摘要掉，也会让 token 计数失真。
权限裁决里，为什么 deny 必须在第一步？
因为后面的步骤包含「绕过模式」和「允许规则」。deny 放后面就可能被放行覆盖。顺序本身就是安全边界。
auto 模式连续被拒几次会退回人工？
连续 3 次，或累计 20 次（DENIAL_LIMITS）。
子 Agent 能绕过父级的 deny 规则吗？
不能：权限模式与规则随父级，工具集按 Agent 定义裁剪；子 Agent 没有独立的权限提升通道。
泄露的源码等于线上二进制吗？
不等于。feature() 是编译期常量折叠，USER_TYPE 是构建期 --define；不同构建裁掉的分支不同，你读到的是并集。
遥测能关吗？关到最彻底会失去什么？
能。DISABLE_TELEMETRY 关分析；CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 连自动更新、版本说明等非必要流量一起关。代价是不再自动更新。

05如果你只有一周

  1. 第 1–2 天：把主循环改成「生成器 + 显式终态」，补上中断补齐逻辑。
  2. 第 3 天：给工具加三个字段 —— 并发安全、结果上限、权限自检。
  3. 第 4 天：实现两级结果预算（单条 + 单轮），超限落盘。
  4. 第 5 天：做三级压缩（清结果 → 折叠 → 摘要），加连续失败熔断。
  5. 第 6 天：把权限裁决写成编号流水线，补测试。
  6. 第 7 天：加一条最简单的子 Agent（只读探索 + 只回灌结论）。
验收标准：让 Agent 在一个真实仓库里连续跑 30 分钟不被上下文打断、不因半截工具调用崩、不在危险命令上静默放行。做到这三条，产品体验会有质变。
