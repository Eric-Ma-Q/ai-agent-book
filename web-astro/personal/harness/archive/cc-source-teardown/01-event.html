第 01 章 · 事故、可信度与法律边界

一次打包疏忽，把产品说明书发到了公网

一个调试用的 .map 文件跟着 npm 包一起发布，里面嵌着全部原始 TypeScript。这一章把时间线、数字冲突和「你能信到什么程度」讲清楚，后面九章的所有结论都建立在这份材料上。

30 秒版

  1. 2026-03-31，@anthropic-ai/claude-code@2.1.88 的 npm 包里带了 cli.js.map，其 sourcesContent 字段是完整未混淆源码；包随后被撤下。
  2. Anthropic 的定性是「发布打包问题、人为失误，不是安全事件」，并称未涉及客户数据或凭证。
  3. 维权动作一度覆盖约 8,100 个 GitHub 仓库，随后收缩为 1 个仓库 + 96 个 fork —— 这个反复本身影响了「哪些副本还在」。
  4. 二手报道的文件数与体积互相矛盾；本报告一律用本地副本实测值（1,932 个文件 / 1,884 个 TS 文件 / 512,664 行）。
  5. 泄露 ≠ 开源：代码没有开源许可证，复制与再分发有法律风险。

01事故是怎么发生的

Source map 是给压缩后的 JS 做「反查原始位置」用的：它不仅能映射行号，还能把原始源码原文塞进 sourcesContent 数组。前端工程里这是调试标配，发布到生产包则是典型事故。

cli.js.map（结构示意，非原文）sourcemap v3 · 只要包里有这个文件，还原源码不需要任何逆向技术
{
  "version": 3,
  "sources": ["../src/main.tsx", "../src/tools/BashTool.ts", "..."],
  "sourcesContent": [
    "// 每个文件未压缩的完整源码，逐字保存",
    "..."
  ],
  "mappings": "AAAA,SAAS,OAAO..."
}

这次的包是 v2.1.88。发现者是安全研究者 Chaofan Shou（@Fried_rice），他在 X 上贴出结论：「Claude Code 的源码通过 npm registry 里的一个 map 文件泄露了」。几小时内 GitHub 上出现大量镜像，fork 数一度超过 star 数 —— 大家都在抢在删库前备份。

02官方怎么说

这次 Claude Code 发布包含了一些内部源码。没有敏感客户数据或凭证被涉及或暴露。这是人为失误导致的发布打包问题，不是安全漏洞。我们正在落实措施避免再次发生。
Anthropic 发言人给 PCMag 的声明，2026-04-01

这段声明定了三件事，后面每一章都要遵守：是内部源码（不是开源）、不涉及客户数据（所以不要从代码里找「用户数据长什么样」）、是流程问题（所以泄露的是构建产物，不是模型）。

没被泄露的东西同样重要：模型权重、训练数据、API 基础设施、用户会话内容都不在此次范围内。任何声称「泄露了模型」的说法可以直接排除。

03维权动作，以及它为什么影响你读到的版本

GitHub 的 DMCA 仓库里先后出现两份通知：先是一份覆盖「约 8,100 个仓库的整个网络」的删除请求，第二天又提交了收缩版，最终只保留 1 个仓库与 96 个 fork 地址。这种「先广后窄」的做法制造了两个后果：

  • 大批无关仓库被误伤（包含只是引用了相似名字的项目），社区对「连坐式下架」的批评集中在这一点；
  • 被下架的副本并没有消失，而是换语言重写（Python、Rust、Bash 版本）继续流传 —— 这也解释了为什么你今天能 clone 到的「源码」质量参差。
读副本的第一个坑：不同镜像可能被删过文件、改过 README、混入二次创作。看到「1900 个文件」的说法先别信，自己数。

05这份材料能支撑什么结论：A / B / C 三级

后面九章会反复用到这个分级。写报告时我把每条断言归到一级，读者可以按级取用。

级别含义典型例子本报告怎么标
A代码里直接可读，行号可查工具并发靠 isConcurrencySafe 判定给 文件:行号
B从代码结构与注释推断，合理但非官方确认某个 flag 对应的产品意图写「推断」并给依据
C只有二手报道支持2025 年 2 月曾发生同类泄露标「据报道」，不当论据
一条实用规则：看到「代码里发现了 X 功能」时，先问它被什么挡住 —— feature() 编译期裁剪、USER_TYPE 账号判断、环境变量、还是服务端下发。挡住它的东西决定了它离上线有多远。

06这份副本本身的完整性

读之前要先知道：它不是一个干净的仓库快照，而是某个对外构建的 sourcemap 反解。三个证据：

  • 部分 .tsx 里 process.env.USER_TYPE 已被替换成字符串 "external"（构建期 --define 的痕迹），同时残留 React Compiler 的 _c() 包装；
  • 有 143 个以上被 import/require 的模块缺失，包括 query/transitions.ts、types/message.ts、assistant/index.ts 这类核心文件；
  • 缺失不全是 bug：编译期常量折叠会把某些 require() 目标整段摇掉，所以「文件不存在」有时正是「这个功能没进这个构建」的证据。
因此：类型定义层面的断言要谨慎（本报告的终态枚举是从 return 字面量反推的）；运行时路径的断言是可靠的（函数体都在）。凡是依赖缺失文件的判断，第 08 章会单独标出。

07如果你想自己复核

包已被撤下，所以直接 npm pack 那个版本通常拿不到。可行的复核路径有两条：

  • 从镜像取副本：GitHub 上仍有个别未被下架的存档仓库（例如把 sourcesContent 还原成目录树的镜像）。取一份后先核对文件数与行数，再开始读。
  • 从任意 sourcemap 验证机制：随便找一个自己项目的 .map，用 Node 读 JSON.parse(fs.readFileSync(map)).sourcesContent，就能看到「源码原文确实在 map 里」这件事，不需要碰泄露副本。
还原思路（伪代码，不针对特定包）—
const map = JSON.parse(readFileSync('cli.js.map', 'utf8'))
map.sources.forEach((src, i) => {
  // sourcesContent[i] 就是该文件的完整原文
  writeFileSync(src.replace('../', ''), map.sourcesContent[i])
})
法律与伦理：只读、只分析、只引用短片段。不要把你 clone 到的副本再发布，也不要把其中的系统提示词搬进自己的产品 —— 那是明确的版权风险。
