第 06 章 · 从弹窗到流水线

权限：每一次「能不能做」都有固定答案

Agent 产品最难的一课是「让它敢做，又不让它乱做」。Claude Code 的做法不是加弹窗，而是把审批做成一条固定顺序的流水线：规则、工具自检、模式、分类器、熔断，各就各位。

30 秒版

  1. 对外只有五种权限模式；auto 要构建开关打开才存在，它用 AI 分类器替代弹窗，连续被拒 3 次或累计 20 次就退回「每次都问」。
  2. 裁决顺序写死在代码里：deny 规则 → 工具自检 → 模式 → 允许规则 → 转成 ask。deny 永远优先，连绕过模式也绕不过。
  3. dontAsk 模式把所有「要问」直接变成「拒绝」—— 这是无头场景（CI）唯一可行的语义。
  4. OS 级沙箱不在 CLI 本体里，而是外部的 @anthropic-ai/sandbox-runtime；开沙箱后，Bash 可以「自动放行但受限执行」。
  5. 企业侧可以从服务端下发策略，直接禁用远端会话、远程控制等功能 —— 代码里是 isPolicyAllowed() 这类开关。

01五种对外模式，一种内部模式

模式决定的不是「能不能用工具」，而是「拿不准的时候怎么办」。命令行与设置只认五个对外模式；auto 要 feature('TRANSCRIPT_CLASSIFIER') 构建设置才存在，bubble 只活在类型层（子 Agent 把请求冒泡给父终端），不接受配置。

模式拿不准时典型使用者备注
default问用户所有人默认档
plan只读探索，不改文件复杂任务开工前计划模式下禁止写
acceptEdits文件编辑自动通过信任度高的日常开发命令仍要问
bypassPermissions全部放行容器 / 一次性环境危险路径仍会拦（安全兜底）
dontAsk直接拒绝CI、无头脚本「问不了」就等价于「不行」
autoAI 分类器判定内部（ant）外部映射为 default

02一次工具调用的十一步

这段代码的编号注释可以直接当规范读。顺序本身就是安全边界：把 deny 放在最前，是为了让任何后面的「放行」都不能翻案。

步骤检查什么结果
1a整工具被 deny 规则命中拒绝，终止
1b整工具有 ask 规则转 ask（沙箱可自动放行的 Bash 除外）
1c工具自己的 checkPermissions()allow / deny / ask / passthrough
1d工具明确拒绝拒绝，终止
1e工具声明「必须人工交互」即使绕过模式也要问
1f内容级 ask 规则（如 Bash(npm publish:*)）优先于绕过模式
1g安全路径检查（.git/、.claude/、shell 配置）绕过模式下也要问
2a模式是否允许（含 plan 模式下继承 bypass）允许，终止
2b整工具被 allow 规则命中允许，终止
3以上都不确定（passthrough）转成 ask
4ask 之后：dontAsk / auto / 交互处理器拒绝 / 分类器 / 弹窗

可迁移结论：审批顺序要写成显式的编号步骤，并有测试覆盖每一步。否则加一个新功能时，很容易把「deny 优先」破坏掉。

03auto 模式：用模型审模型

auto 把「问用户」换成「问一个分类器」。分类器看到的是工具给它的精简输入（toAutoClassifierInput()），而不是完整文件内容 —— 既省 token，也避免把代码送进判定请求。

utils/permissions/denialTracking.ts12-16 · 连续 3 次或累计 20 次被拒，退回人工确认
export const DENIAL_LIMITS = {
  maxConsecutive: 3,
  maxTotal: 20,
} as const

还有一个容易被忽略的细节：进入 auto 模式时，代码会把「等价于任意代码执行」的允许规则剥掉。比如 Bash(python:*) —— 允许它等于允许一切，分类器也就形同虚设。

utils/permissions/dangerousPatterns.ts3-8
* An allow rule like `Bash(python:*)` or `PowerShell(node:*)` lets the model
 * run arbitrary code via that interpreter, bypassing the auto-mode classifier.
 * These lists feed the isDangerous{Bash,PowerShell}Permission predicates in
 * permissionSetup.ts, which strip such rules at auto-mode entry.
换来什么日常操作不用每次点确认，长任务不会被人肉审批卡死。
付出什么分类器会犯错：既可能放过危险命令，也可能误拒正常操作；所以要有「连续被拒就退回人工」的熔断，以及随时可切的模式。

04沙箱：不在这个仓库里

一个常见误解是「Claude Code 自带 OS 级沙箱」。源码给出的答案是：CLI 只做适配层，真正的隔离来自外部包 @anthropic-ai/sandbox-runtime（macOS 用 seatbelt，Linux 用 bubblewrap）。

utils/sandbox/sandbox-adapter.ts1-20
/**
 * Adapter layer that wraps @anthropic-ai/sandbox-runtime with Claude CLI-specific integrations.
 * This file provides the bridge between the external sandbox-runtime package and Claude CLI's
 * settings system, tool integration, and additional features.
 */
import type { ... } from '@anthropic-ai/sandbox-runtime'
import { SandboxManager as BaseSandboxManager, ... } from '@anthropic-ai/sandbox-runtime'
  • 沙箱开启后，Bash 可以配置成「被沙箱包裹就自动放行」（isAutoAllowBashIfSandboxed）—— 用隔离换掉逐条确认；
  • 被排除的命令（需要网络、需要写系统目录）仍然要遵守 ask 规则；
  • 依赖检查：Linux/WSL 缺 bubblewrap 时给出安装提示，而不是静默降级。
结论：如果你要抄它的安全模型，抄的是「权限流水线 + 外部沙箱适配」这个分层，而不是某个内置沙箱实现 —— 后者需要你自己接 OS 能力。

05规则语法与作用域

规则是三态：allow / deny / ask，写进设置文件后按作用域合并：企业托管 → 用户 → 项目 → 本地 → 会话。语法上有几个必须知道的形状：

写法含义坑
Bash(git:*)所有以 git 开头的命令前缀匹配，不是正则
Bash(npm publish:*)精确到子命令内容级 ask 优先于绕过模式
mcp__github整个 MCP 服务器的工具等价于 mcp__github__*
Read(./src/**)路径 glob越界与符号链接另有校验

规则被覆盖时，代码会主动检测「影子规则」并提示（shadowedRuleDetection）—— 因为一条被上层覆盖的 allow 规则，会让用户以为自己放行了，其实没有。

06企业控制面与紧急开关

两个独立通道：策略限制（能用什么功能）与托管设置（默认配置长什么样）。策略是「缺省即允许」的白名单式模型：只有被明确 block 的 key 才会拒绝。

services/policyLimits/types.ts5-10
* Only blocked policies are included. If a policy key is absent, it's allowed.
restrictions: z.record(z.string(), z.object({ allowed: z.boolean() }))

实际用到的 key 比如 allow_remote_sessions、allow_remote_control、allow_product_feedback —— 企业可以直接关掉「远程会话」这类能力，而不需要发版。

产品含义：「安全」在这里是一个可远程调整的策略面，而不是一个写死的开关。好处是能应急；代价是用户看到的可用功能可能在某天突然消失。

08这套设计的三条硬规则

  • 拒绝不可被绕过：deny 在第一步，连 bypassPermissions 都翻不了案；
  • 不确定就降级：分类器连续被拒就退回人工，而不是继续自动放行；
  • 危险先于便利：.git/、shell 配置文件这类路径，在任何模式下都要确认。
