A项目深挖必准备一个 3 分钟项目故事

01团队里是怎么分工的？你本人具体负责什么？

字节、美团部分待核原帖

框架项目背景一句话 → 团队规模与分工 → 你负责的模块 → 量化结果。别说“都参与”，要能说清边界。

注：字节可核；美团这条在 659 条语料里回查不到。

02你在做这个产品当中，遇到最难的问题是什么？

字节、携程、美团部分待核原帖

框架问题是什么（技术/资源/方向）→ 你为什么判定它最难 → 解决路径 → 复盘学到了什么。

注：携程可核；字节、美团未回查到。

03如果重来一次，你会做什么不同的事情？

字节 ×2可核原帖

框架承认一个真实失误点 → 当时为什么那样做 → 现在会换什么做法 → 这个教训怎么用到下一个项目。

04XX 项目用的 basemodel 是什么？为什么选这个模型？

字节、理想可核原帖

框架候选模型对比维度（效果/成本/延迟/生态/合规）→ 选型实验怎么做 → 最终取舍。理想还会追问“怎么验证某个模型就是合适的”。

注：理想对应同义题“怎么选的基模，以及 workflow 如何设计”，可核。

05项目的目标/标准是怎么定的？为什么是这个数？

字节可核原帖

框架目标拆解逻辑（自上而下/自下而上）→ 基准数据来源 → 理想态定义 → 标准还有没有改进空间（主动说迭代）。

注：原话是“500 个的目标是怎么定的、理想态是怎么定的”。

B技术理解AI PM 的分水岭

06RAG 解决了大模型的什么问题？

字节；淘天另考 RAG 客服全案可核原帖

框架幻觉/知识时效/私域数据三痛点 → 检索-增强-生成链路 → 局限（检索质量天花板、长尾 badcase）。能画出链路加分。

07单 Agent 和多 Agent 的差异是什么？为什么用 Agent 不用 workflow？

字节 ×2、快手部分待核原帖

框架自由度谱系（workflow < 单 Agent < 多 Agent）→ 规划/记忆/工具调用能力差异 → 成本与可控性取舍 → 判断标准（任务复杂度 vs 确定性）。

注：字节可核；快手那条来自二手归纳文章（rugoi），不是面经原帖。

08Agent 失败了怎么设计兜底？

字节 ×2可核原帖

框架分层兜底（重试 → 降级模型/规则 → 人工接管 → 明确告知用户）→ 举例（订票没票/工具调用失败）→ 兜底自身的指标（兜底率、人工接管率）。

09LoRA 微调训练集怎么构建？微调前后怎么判断能力提升？

字节 ×2可核原帖

框架数据来源（badcase 回流/人工标注/合成）→ 规模与配比 → 评测集隔离 → 对比指标（任务指标 + 通用能力回归）。

10Agent 和 Siri 这类传统助手的核心差别在哪？

字节可核原帖

框架意图理解（规则/单轮 → 自主规划多步）→ 工具使用 → 记忆与个性化 → 失败模式不同。

16你们是怎么评估 AI 产品效果的？评测体系怎么搭？

17这个产品的北极星指标是什么？指标体系怎么搭？

18AI 功能怎么做 A/B 测试？

框架假设 → 分流（用户/请求粒度，注意 AI 的随机性）→ 核心指标 → 显著性与周期。淘天给了完整场景：AI 商品文案对点击/转化的影响。

19一个 AI 功能短期数据好、长期数据差，你的分析框架是什么？
